# M0.2a work package — versioned IPC protocol and framing

## Goal

Implement the low-risk, transport-independent portion of M0.2: protocol-v1 request/response/error envelopes and bounded newline-delimited JSON framing. Socket creation, daemon startup, process launching, filesystem paths, and LaunchAgent behavior remain out of scope and owner-gated.

## Source requirements

- `docs/ROADMAP.md:21-22` requires JSON framing, `daemon.ping`, versioned envelopes, and client auto-start/retry; this slice covers only framing/envelopes.
- `docs/ARCHITECTURE.md:135-159` defines newline-delimited JSON request/response frames, method names, the error triple, and major-version rejection.
- `docs/ARCHITECTURE.md:36-45` keeps clients thin and the daemon as single writer.
- `docs/REVIEW_STANDARDS.md` applies to all structured verdicts and error boundaries.

Do not edit CLI, `cmd/**`, store, sockets, daemon code, CI, or docs.

## Required behavior

- Define protocol version 1 request and response envelopes matching Architecture section 5. Preserve `params` and `result` as `json.RawMessage` so method payloads remain additive.
- Define the stable error shape with `code`, `message`, `fix`, and optional queue position. Constructors/validation must reject an error missing any required triple field.
- Encode exactly one compact JSON object plus newline per frame.
- Decode one newline-delimited frame at a time with an explicit sane maximum frame size; return deterministic typed/protocol errors for malformed JSON, empty frames, oversized frames, missing IDs/methods, and unsupported versions.
- Unsupported versions must produce a stable error code and exact upgrade/status fix command; do not silently accept newer versions.
- Do not implement method dispatch or special-case `daemon.ping` yet. Do not create sockets or spawn processes.
- Add table-driven tests for request/response round trips, multiple frames on one stream, malformed/empty/oversized input, validation failures, required error triple, and unsupported version behavior.
