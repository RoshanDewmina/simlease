# M0.4 work package — `simurgh doctor`

## Goal

Implement `simurgh doctor`: a read-only diagnostic command that checks Xcode
presence, `simctl` availability, at least one installed iOS runtime, socket
file permissions, and daemon liveness — printing a stable `code`/`message`/
`fix` triple for every failing check, and exiting 0 only when every check is
green. This is the last M0 package; its exit-0 run is half of the M0
milestone integration gate (`docs/ROADMAP.md:29-32`).

## Source requirements

- `docs/ROADMAP.md:25-26` — "M0.4 doctor: checks Xcode/simctl presence,
  runtimes, socket perms, daemon liveness; every failure prints a `fix`."
- `docs/ROADMAP.md:29-32` — M0 gate: `simurgh daemon run &` then
  `simurgh doctor` must exit 0, all checks green, `[mac]`.
- `docs/ARCHITECTURE.md:37-40` — "Public Apple interfaces only... No client
  ever calls `simctl` mutatingly on Simurgh-managed devices; reads (e.g.
  `doctor`) may." Doctor may run **read-only** `simctl`/`xcodebuild` commands
  only (list/version-style). No `simctl create|boot|shutdown|delete|erase`.
- `docs/ARCHITECTURE.md:237` — `simurgh doctor` in the CLI surface: "env
  checks: Xcode, simctl, runtimes, daemon, socket perms".
- `docs/ARCHITECTURE.md:244-246` — CLI conventions: `--json` on every
  command; exit codes 0 ok, 2 queued/blocked, 3 invalid input,
  **4 environment problem**, 5 internal. Doctor uses exit 0 (all green) or
  exit 4 (one or more checks failed) — never 2/3/5 for a normal failing
  check.
- `docs/REVIEW_STANDARDS.md` — every user-facing error/check failure needs
  code + message + fix; this is a boundary command so failures must carry
  the full triple, not just an internal error.

## Exact write-set

- `internal/cli/doctor.go` (new) — the existing `internal/cli` package
  (currently a `doc.go` stub from M0.1) gains the testable check logic.
  Define a `Check` struct `{Name, Code string; OK bool; Message, Fix string}`
  and a `RunChecks(ctx context.Context, opts DoctorOptions) []Check`. Each
  check is independent — one failure must not prevent the others from
  running (collect-all, not fail-fast). `DoctorOptions` carries injected
  seams so the whole thing is unit-testable without a real Mac:
  - `XcodeVersion func(ctx context.Context) (string, error)` (prod: run
    `xcodebuild -version`)
  - `SimctlRuntimes func(ctx context.Context) ([]string, error)` (prod: run
    `xcrun simctl list runtimes -j` and parse installed runtime names; a
    parse/exec failure is a check failure, not a panic)
  - `SocketPath string` — stat this path; check exists, is a socket
    (`os.ModeSocket`), and mode is exactly `0600`.
  - `DialPing func(ctx context.Context) error` — a **non-auto-starting**
    liveness probe (short-timeout direct dial + `daemon.ping` request/
    response over the M0.2a/M0.2b protocol; do NOT use `ipc.Dial`'s
    auto-start-and-spawn behavior here — doctor must never launch a daemon
    as a side effect of a read-only diagnostic).
  Five checks total: Xcode present, simctl present (implied by the runtimes
  call succeeding — do not shell out twice for the same fact), at least one
  installed iOS runtime, socket file mode 0600, daemon responds to ping.
- `internal/cli/doctor_test.go` (new) — table-driven tests over `RunChecks`
  with every seam faked: all-green, each individual check failing alone
  (verify the other four still run and report — collect-all, not fail-fast),
  and the exit-code mapping (0 vs 4) as a pure function of the results.
- `cmd/simurgh/doctor.go` (new) — thin CLI wiring only, mirroring
  `cmd/simurgh/daemon.go`'s pattern: resolve `DefaultSocketPath()`, build the
  production `DoctorOptions` (real `exec.CommandContext` seams, a raw
  short-timeout `net.DialTimeout` + one `daemon.ping` round trip for
  `DialPing` — reuse `internal/ipc`'s `Encoder`/`Decoder` directly, not
  `ipc.Dial`), call `internal/cli.RunChecks`, print each check's
  name/status/message/fix to stdout (plain text) and support `--json`
  (array of the `Check` structs), then `os.Exit(0)` or `os.Exit(4)`.
- `cmd/simurgh/main.go` — wire the `doctor` subcommand only.

Do not edit `internal/ipc`, `internal/store`, `internal/broker`,
`internal/safety`, `internal/provisioner`, CI config, or any doc other than
`docs/plans/orchestrator-state.md` (orchestrator updates that, not the coder).

## Explicitly out of scope

- No `simctl create|boot|shutdown|delete|erase` or any mutating call.
- No daemon auto-start. If the daemon isn't running, `daemon liveness` is
  simply a failing check with `fix: "simurgh daemon run"` — doctor never
  spawns anything.
- No `xcodebuild -downloadPlatform` or any runtime-installation flow — a
  missing runtime is a failing check with a `fix` hint only (exact
  `xcodebuild -downloadPlatform iOS` string, per
  `docs/ARCHITECTURE.md:126-127`'s runtime-resolution error pattern).
- No config file (`config.yaml`) reading.
- No JSON schema/versioning beyond a flat array for `--json`.

   doctor against the same `SIMURGH_HOME`, confirming exit 0 and all five
   checks green; then run once more with `--json` and paste the output.

Return verbatim output, changed files, and diff stat. Do not commit.

## Risk class

`low` — read-only diagnostics only (no simulator mutation, no destructive
filesystem operation, no daemon spawn). Standard pipeline (fresh cross-model
review, not mandatory Sonnet-or-orchestrator review).
