# M1.1 work package — lease broker (acquire/renew/release/get/list/wait)

## Goal

Implement the in-memory lease lifecycle engine: the `Lease` state machine
(`QUEUED → PROVISIONING → ACTIVE → RELEASED`, plus `CANCELLED`/`FAILED`),
a FIFO queue per `DeviceSpec`, a capacity gate, and the six broker
operations (`Acquire`, `Renew`, `Release`, `Get`, `List`, `Wait`). This is
the foundational package M1.2 (provisioner), M1.3 (watcher/reaper), and
M1.5 (CLI) all build on — get the types and state machine right here.

**Real device provisioning (M1.2) does not exist yet.** This package
depends only on a small `Provisioner` interface it defines itself; a fake
implementation drives all unit tests. Do not call `simctl`/`xcodebuild`
anywhere in this package.

## Exact write-set

- `internal/broker/types.go` (new) — `Lease`, `LeaseState` (string enum:
  `queued|provisioning|active|expiring|released|cancelled|failed|reclaimed`
  — `expiring`/`reclaimed` are declared for M1.3's use but never set by
  this package), `Owner{PID int; PPID int; Agent string; SessionID string}`,
  `DeviceSpec{Platform, Model, Runtime string}`, `Device{UDID, Name,
  Runtime string; CloneOf string; Booted bool}`, `Connection{Transport
  string}` (v0 always `{"transport":"local"}`), `Timeouts{Inactivity,
  Hard time.Duration}`. Match `docs/ARCHITECTURE.md:77-105` field-for-field.
- `internal/broker/provisioner.go` (new) — the interface this package
  depends on: `type Provisioner interface { Provision(ctx context.Context,
  spec DeviceSpec) (Device, error) }`. No implementation here — M1.2 supplies
  the real one; this package's tests use a fake.
- `internal/broker/broker.go` (new) — `Broker` type: `New(opts
  BrokerOptions) *Broker`. `BrokerOptions{Capacity int; Provisioner
  Provisioner; Clock func() time.Time; PressureOK func() (bool, string)}`
  (all fields have sane defaults if zero: `Capacity` computed via the
  formula from `runtime.NumCPU()`/a injected total-RAM seam — do not shell
  out to `sysctl` in this package, accept RAM via an injected
  `TotalRAMBytes func() (uint64, error)` seam so it's fake-able; `Clock`
  defaults to `time.Now`; `PressureOK` defaults to always-OK).
  - `Acquire(ctx, req AcquireRequest) (Lease, error)`: `AcquireRequest{Spec
    DeviceSpec; Labels map[string]string; TTL time.Duration; ReuseIfExists,
    Wait, ReleaseOnPIDExit bool; Owner Owner}`. If capacity allows (active
    count for matching spec key < effective capacity) and pressure is OK,
    transitions QUEUED→PROVISIONING synchronously, calls
    `Provisioner.Provision`, then PROVISIONING→ACTIVE on success or
    →FAILED on error (FAILED result returned as an error with a retry-hint
    fix, per architecture's "provision-failure → FAILED + retry hint").
    If capacity is full: lease stays QUEUED, enters the FIFO queue for that
    spec key, and either (`Wait=false`) returns immediately with a
    `CAPACITY_QUEUED` error carrying `queuePosition`, or (`Wait=true`)
    blocks (context-cancellable) until a slot frees and this lease reaches
    ACTIVE or the context is cancelled/times out.
  - `Renew(ctx, leaseID string, ttl time.Duration) (Lease, error)`: must be
    ACTIVE; extends `ExpiresAt` from `Clock()`, bumps `HeartbeatAt`; not-found
    or wrong-state → typed error triple.
  - `Release(ctx, leaseID string) (Lease, error)`: ACTIVE or QUEUED →
    RELEASED (or CANCELLED if it was still QUEUED — architecture's diagram
    labels the queued-cancel path CANCELLED, the active-release path
    RELEASED; use CANCELLED only for a release while still QUEUED, RELEASED
    otherwise); frees capacity and pops the next FIFO-queued request for
    that spec key, starting its provisioning. **Do not call any deletion or
    `simctl` here** — actual device teardown is M1.3 reaper's job; this
    method's job is state-transition + queue-advance only. Leave a doc
    comment noting the M1.3 hook point.
  - `Get(leaseID string) (Lease, bool)`, `List(filter ListFilter) []Lease`
    (`ListFilter{Labels map[string]string}` — selector match, AND semantics
    across keys, per `docs/ARCHITECTURE.md:244` label-selector convention).
  - `Wait(ctx, leaseID string) (Lease, error)`: blocks until the lease
    reaches a terminal-for-waiting state (ACTIVE, FAILED, CANCELLED,
    RELEASED) or ctx is done.
  - All public errors are one of a small set of typed sentinel/struct errors
    (`ErrLeaseNotFound`, `ErrInvalidState`, a `CapacityQueuedError{Position
    int}`, a `ProvisionFailedError{Cause error}`) each mapping to a
    code/message/fix triple via a `NewError`-style helper matching
    `internal/ipc`'s pattern (do not import `internal/ipc` — duplicate the
    tiny triple-error helper locally to keep this package dependency-free of
    the transport layer; note the duplication in a comment for a future
    shared-package cleanup, do not attempt that cleanup now).
- `internal/broker/queue.go` (new, optional — inline in broker.go is fine
  too if it stays readable) — the per-spec-key FIFO queue and capacity
  bookkeeping, mutex-guarded.
- `internal/broker/broker_test.go`, `internal/broker/queue_test.go` (new) —
  must include, at minimum: (1) two concurrent `Acquire` calls with the same
  spec and capacity ≥2 against a fake `Provisioner` returning distinct
  UDIDs → both end ACTIVE with different `Device.UDID`; (2) capacity=1, two
  `Acquire` calls same spec, `Wait=false` → first ACTIVE, second returns
  `CapacityQueuedError{Position:1}`; (3) capacity=1, `Wait=true` on the
  second → blocks until `Release` on the first frees the slot, then the
  second reaches ACTIVE; (4) `Release` while QUEUED → CANCELLED, never
  calls the fake provisioner; (5) provisioner returning an error → lease
  FAILED, `Acquire` returns a typed `ProvisionFailedError`; (6) `-race`
  clean under `go test -race` with many concurrent `Acquire`/`Release`
  pairs (a stress test, bounded iteration count, not a hang risk); (7)
  `List` label-selector AND-match; (8) capacity formula unit tests against
  injected fake CPU/RAM seams, including the config-override path.
- `internal/broker/doc.go` — package comment describing scope and the
  M1.2/M1.3/M1.4 boundary (provisioner injected, no deletion, no watcher).

Do not edit `internal/store`, `internal/ipc`, `internal/safety`,
`internal/provisioner`, `internal/watcher`, `internal/reaper`, CI config, or
any doc other than `docs/plans/orchestrator-state.md`.

## Explicitly out of scope

- Persistence to `~/.simurgh/state.json` (`internal/store` integration).
  This package is in-memory only for M1.1; wiring it to the store's journal
  (including the additive `State` schema change store's own doc comment
  anticipates) is a **separate, later package** so this diff stays
  reviewable. Note the eventual hook in a doc comment; do not implement it.
- Any real `simctl`/`xcodebuild` call, warm-template selection, or clone
  naming (`simurgh-clone[...]`) — that's M1.2.
- PID liveness, heartbeat/TTL/inactivity/hard-timeout-driven reclamation,
  orphan scan — that's M1.3 watcher/reaper. This package's `Renew` only
  updates timestamps; nothing in this package ever transitions a lease to
  `RECLAIMED`.
- Any deletion of any kind (that's exclusively M1.4 safety + M1.3 reaper).
- IPC/CLI/MCP wiring (`daemon.*` methods, `simurgh acquire` etc.) — later
  packages consume this broker's Go API.
- `config.yaml` reading, warm pool, priority/preemption queueing.

If implementing the required behavior turns out to need any of the above,
stop and report back to the orchestrator rather than expanding scope.
