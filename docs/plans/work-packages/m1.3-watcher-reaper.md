# M1.3 work package — watcher + reaper (reclamation)

## Goal

Implement `internal/watcher` (decides what to reclaim: PID death, TTL/
heartbeat/inactivity/hard-timeout expiry) and `internal/reaper` (acts on
that decision: shuts down and deletes the clone via `internal/safety`,
deletes the lease directory via `internal/safety`, and runs a live orphan
scan). This closes the state-machine loop `ACTIVE → RECLAIMED` that M1.1
declared (`LeaseReclaimed`) but never set.

## Known, deliberate scope gap — read before writing code

`docs/ROADMAP.md`'s `[mac]` GATE for M1 includes "daemon SIGKILL
mid-provision → restart reconciles with zero orphans and zero non-simurgh
deletions." That scenario requires the broker to persist lease state to
`~/.simurgh/state.json` via `internal/store` so a **restarted** daemon
process can reconstruct which UDIDs it owned before the crash. **That
persistence wiring does not exist yet** — M1.1 deliberately scoped it out
("a separate, later package... in-memory only for M1.1"; see
`docs/plans/orchestrator-state.md`'s M1.1 evidence entry). This package
CANNOT and MUST NOT attempt to build that wiring as a surprise scope
expansion — it is a real, tracked gap, not this package's job. What M1.3
CAN and MUST deliver without persistence: (1) in-process reclamation
(PID death / TTL / heartbeat / hard-cap, all driven off the broker's live
in-memory lease map — no restart involved, no persistence needed) and (2)
a live orphan scan that diffs the real `simctl` device list against the
broker's *currently in-memory* known lease UDIDs (this catches devices
Simurgh created but lost track of within the SAME process lifetime — e.g.
a lease whose provisioning succeeded but the broker's bookkeeping failed
partway — not devices orphaned by a full daemon crash-and-restart, which
needs the store wiring). Implement the restart-safe cross-process
reconciliation as a stubbed, clearly-commented extension point
(`Reconcile` no-op or TODO) rather than faking it. Note this gap explicitly
in your final report.

## Source requirements

- `docs/ARCHITECTURE.md:107-133` (§4) — state diagram: `ACTIVE →
  RECLAIMED (reaper: shutdown+delete clone, purge env per policy)`.
  Watcher checks: "owner PID alive (`kill(pid,0)`), heartbeat age,
  inactivity, hard cap." "Reclamation is idempotent and crash-safe: reaper
  re-derives work from (journal ∪ device-name scan)" — the journal half is
  the deferred gap above; the device-name-scan half (orphan scan by
  `internal/safety.IsSimurghManagedName`) is in scope.
- `docs/ARCHITECTURE.md:248-255` (§10) — **"Reaper never runs destructive
  actions during the first 10s after start (reconciliation window)."**
  This is a hard requirement even without persistence: whatever triggers
  the reaper's orphan-scan path must respect a configurable/injected
  startup grace period.
- `docs/ROADMAP.md:36-53` (M1 GATE unit) — "SIGKILL'd owner → RECLAIMED
  within one watcher interval" (in scope, no persistence needed — kill a
  test child/fake PID, watcher's next tick notices `kill(pid,0)` fails,
  reclaims within one tick) and "prune plan never contains a
  non-simurgh-named device" (already proven by `internal/safety`'s
  property tests — this package's orphan scan must call
  `safety.IsSimurghManagedName`, not reimplement the pattern, so that
  guarantee carries over).
- `internal/safety` (existing, read-only) — `DeleteSimulatorClone`,
  `DeleteLeaseDir`, `IsSimurghManagedName`, the `DeviceLister`/
  `DeviceDeleter` interfaces. This package is the ONLY caller of those
  destructive functions from product code so far — treat every call site
  with care (never call `simctl`/`os.RemoveAll` directly, always through
  safety).
- `internal/broker` (existing) — needs one new exported method (see
  write-set) so a lease can actually reach `RECLAIMED`; everything else
  about the broker's public API is stable and must not change behavior.

## Exact write-set

- `internal/broker/broker.go`, `internal/broker/broker_test.go` — add
  `func (b *Broker) Reclaim(ctx context.Context, leaseID string) (Lease,
  error)`: same shape as `Release` (ACTIVE → terminal state, frees
  capacity, advances the FIFO queue for that spec key) but the terminal
  state is `LeaseReclaimed`, not `LeaseReleased`. Reuse `Release`'s
  internal structure/helpers rather than duplicating the queue-advance
  logic — factor a small shared private helper if that keeps it DRY, but
  do not change `Release`'s existing behavior or its tests' assertions.
  `Reclaim` on a non-ACTIVE lease is an error (same `invalidState` shape
  Release already uses for non-ACTIVE/non-QUEUED states). Add a focused
  test or two for `Reclaim` alongside the existing `Release` tests. **This
  is the only permitted edit to `internal/broker`** — do not touch
  anything else in that package.
- `internal/watcher/watcher.go` (new) — `Watcher` type: `New(opts
  WatcherOptions) *Watcher`. `WatcherOptions{Broker BrokerLister; Now func()
  time.Time; IsProcessAlive func(pid int) bool; DefaultInactivity,
  DefaultHardCap time.Duration}` (sane defaults; `IsProcessAlive` real impl
  uses `syscall.Kill(pid, 0) == nil` — Darwin-only is fine, this whole
  product is macOS-only — behind the injected seam so tests never touch
  real PIDs unpredictably). `BrokerLister` is a small interface
  (`List(ListFilter) []Lease`, matching `internal/broker`'s real method
  shape) so this package doesn't need a concrete `*broker.Broker` import
  cycle concern — actually importing `internal/broker` directly for its
  types (`Lease`, `ListFilter`) is fine and expected (same one-directional
  dependency pattern as `internal/provisioner`), just keep the *broker
  instance* itself accessed through a small interface so fakes are easy in
  tests.
  - `Tick(ctx context.Context) []ReclaimDecision`: scans all ACTIVE
    leases via `Broker.List(ListFilter{})`, and for each, in this priority
    order, decides whether to reclaim and why: (1) `ReleaseOnPIDExit &&
    !IsProcessAlive(Owner.PID)` → reclaim, reason `"owner process exited"`;
    (2) `!IsProcessAlive(Owner.PID)` (PID death check applies regardless of
    `ReleaseOnPIDExit` per architecture's "owner PID alive" watcher check —
    confirm this reading against the spec text and implement accordingly)
    → reclaim, reason `"owner process not alive"`; (3) `Timeouts.Hard > 0 &&
    Now().Sub(AcquiredAt) > Timeouts.Hard` → reclaim, reason `"hard
    timeout"`; (4) `Timeouts.Inactivity > 0 && Now().Sub(HeartbeatAt) >
    Timeouts.Inactivity` → reclaim, reason `"inactivity timeout"`; (5)
    `Now().After(ExpiresAt)` (TTL expired, never renewed) → reclaim, reason
    `"ttl expired"`. `Tick` itself does NOT call `Broker.Reclaim` or
    `internal/safety` — it is a pure decision function returning
    `[]ReclaimDecision{LeaseID, Reason string}` so it's directly unit
    testable without any side effects (mirrors the design principle behind
    `internal/safety.ValidateDeviceDeletion` being separate from
    `DeleteSimulatorClone`). A separate small `Run(ctx, interval, onDecide
    func([]ReclaimDecision))` loop wrapper calls `Tick` on a ticker and
    invokes the callback — production wiring (owned by a later CLI/daemon
    package, not this one) passes a callback that calls `Broker.Reclaim`
    then the reaper.
- `internal/watcher/watcher_test.go` (new) — table/scenario tests for each
  of the 5 decision branches independently, a test proving a healthy
  ACTIVE lease (alive PID, fresh heartbeat, within TTL, no hard cap hit)
  produces zero decisions, and the specific roadmap scenario: fake
  `IsProcessAlive` returns false for a specific PID → `Tick` reclaims that
  lease's ID within a single call (no sleep/interval needed to prove this
  at the unit level — `Run`'s ticker wrapper is a thin, separately-tested
  loop, not where the core logic lives).
- `internal/reaper/reaper.go` (new) — `Reaper` type: `New(opts
  ReaperOptions) *Reaper`. `ReaperOptions{LeasesRoot string; Lister
  safety.DeviceLister; Deleter safety.DeviceDeleter; StartedAt func()
  time.Time; Now func() time.Time; ReconciliationWindow time.Duration}`
  (`ReconciliationWindow` defaults to 10s per architecture §10).
  - `Reclaim(ctx context.Context, lease broker.Lease) error`: for a lease
    that has already been transitioned to `RECLAIMED` by the broker
    (this function does not itself decide reclaim-worthiness — that's the
    watcher's job — it only acts), calls `safety.DeleteSimulatorClone`
    with the lease's `Device.UDID` if `Device != nil` (a lease that never
    left QUEUED/PROVISIONING has no device to delete — handle that as a
    no-op, not an error) and `safety.DeleteLeaseDir` with the injected
    `LeasesRoot` and the lease ID. Both are independently idempotent
    (missing device/path is fine per `internal/safety`'s existing
    contract) — this function should attempt both even if one fails, and
    return a combined error only if something genuinely went wrong (not
    "already gone").
  - `ScanOrphans(ctx context.Context, knownLeaseUDIDs map[string]bool)
    ([]string, error)`: **refuses to run (returns immediately, empty
    result, no error) if `Now().Sub(StartedAt()) < ReconciliationWindow`**
    — the hard 10s-after-start requirement, tested explicitly. Otherwise
    lists live devices via `Lister.ListDevices`, filters to
    `safety.IsSimurghManagedName(device.Name)`, excludes anything whose
    UDID is in `knownLeaseUDIDs` (owned by a currently-tracked in-memory
    lease — not an orphan), and returns the remaining UDIDs as orphan
    candidates. **Does not delete them itself** — returns the list for the
    caller to decide (mirrors `ValidateDeviceDeletion` vs
    `DeleteSimulatorClone`'s validate/act separation); note in a doc
    comment that a future caller wanting to actually reclaim these must
    call `safety.DeleteSimulatorClone` per UDID, going through the same
    live-revalidation `internal/safety` already performs (so even an
    orphan-scan false positive can't cause an unsafe delete — the safety
    package re-checks the name regardless of how the UDID reached it).
- `internal/reaper/reaper_test.go` (new) — fake `DeviceLister`/
  `DeviceDeleter`: `Reclaim` deletes the right device and lease dir (use
  `t.TempDir()` as `LeasesRoot`, real filesystem, confirm the dir is
  actually gone); `Reclaim` on a lease with `Device == nil` doesn't call
  delete on anything; `ScanOrphans` returns nothing before the
  reconciliation window elapses (fake clock) and returns unknown
  `simurgh-clone[...]`/`simurgh-warm[...]` devices after it, while
  excluding known UDIDs and non-managed names (reuse
  `safety.IsSimurghManagedName`'s existing adversarial coverage by
  reference — do not re-test the regex itself here, just that this
  package calls it correctly).
- `internal/reaper/integration_test.go` (new) — `//go:build darwin_sim`
  tagged: create a real throwaway `simurgh-clone[...]` device (self-
  contained helper, same pattern as M1.2/M1.4's integration tests — do not
  import `internal/provisioner`), confirm `Reaper.Reclaim` against a fake
  lease pointing at it actually deletes it via the real `internal/safety`
  path, confirm `ScanOrphans` (after faking `StartedAt` far enough in the
  past to clear the reconciliation window) finds a real throwaway orphan
  device the test created directly via `simctl` (bypassing any lease
  bookkeeping, simulating a true orphan) and does NOT list the real
  pre-existing `simurgh-base[...]` device (bases are never
  `IsSimurghManagedName`). Clean up every device this test creates itself.
- `internal/watcher/doc.go`, `internal/reaper/doc.go` — package comments,
  including the persistence/crash-recovery scope-gap note from above in
  `reaper/doc.go` specifically (so it's discoverable in-repo, not just in
  this spec).

Do not edit `internal/store`, `internal/ipc`, `internal/provisioner`,
`internal/safety`, `internal/cli`, `cmd/simurgh`, CI config, or any doc

## Explicitly out of scope

- Cross-process/restart crash recovery (the persistence-dependent gap
  described above) — stub or TODO, do not fake.
- Actually wiring `Watcher.Run`'s callback to call `Broker.Reclaim` +
  `Reaper.Reclaim`/`ScanOrphans` end-to-end inside a running daemon loop —
  that's daemon/CLI wiring, a later package. This package delivers the two
  correct, independently-tested decision/action engines; gluing them into
  `cmd/simurgh daemon run`'s actual event loop is out of scope here.
- Purging isolation-env directories beyond the lease dir itself (M2 scope
  — `IsolationEnv` subdirectories like `DerivedData`/`ModuleCache` live
  under the same per-lease dir, so `DeleteLeaseDir` already removes them
  as part of the lease dir's recursive delete; no separate per-subdir
  logic needed here).
- Any new destructive primitive — every delete in this package's write-set
  must go through the existing `internal/safety` functions, zero new ones.

## Risk class

`low` for this package's own code (it never calls `os.RemoveAll`/`simctl
delete` directly — always through the already-reviewed `internal/safety`).
Standard review pipeline. **However**: the decision logic (what counts as
reclaimable, what counts as an orphan) directly determines what
`internal/safety` is asked to delete, so the reviewer must treat the
*decision* logic with sensitive-package-level scrutiny even though the
package itself is classified low risk — a bug that reclaims a healthy
ACTIVE lease, or that treats a non-orphan as an orphan, is a real-world
"my simulator got deleted while I was using it" bug even though no line
of code here is directly destructive.
