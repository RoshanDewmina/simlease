# M1.4 work package — centralized deletion safety guards

## Goal

Implement `internal/safety`: the ONE place in the whole codebase permitted
to perform recursive filesystem deletion or simulator device deletion.
Every future destructive call (M1.3 reaper, M2 prune, CLI `prune --apply`,
warm-template removal) must route through this package — no exceptions,
per `docs/ARCHITECTURE.md` §2 and §12. This is the single most
safety-critical package in the product: a bug here deletes a user's real
files or real simulators. Treat every line with that weight.

## The invariant, precisely (docs/ARCHITECTURE.md:70-75, non-negotiable)

> Recursive deletion is only ever permitted on (a) paths strictly under
> `~/.simurgh/leases/`, and (b) simulator devices whose name matches
> `^simurgh-(clone|warm)\[.*\]$` AND whose UDID appears in Simurgh state or
> matches the name pattern via `simctl list -j`.

Read clause (b) as: the device's *live* name (re-queried from `simctl`
right now, never trusted from a caller-supplied string) must match the
anchored pattern. Whether the UDID also appears in an injected "known
lease UDIDs" set is additional corroboration/audit context (distinguishes
"deleting a lease I own" from "reclaiming an orphan with no journal
entry"), not a way to bypass the live name check — the live regex match is
never optional.

## Exact write-set

- `internal/safety/paths.go` (new):
  - `ValidateLeasePath(leasesRoot, leaseID string) (string, error)`: the
    ONLY way to obtain a deletable path. Takes a `leasesRoot` (injected,
    never resolves `~/.simurgh` itself — same convention as `internal/store`
    and `internal/ipc`) and a `leaseID` string. Validates `leaseID` against
    a strict allowlist pattern (must match the broker's actual ID shape,
    e.g. `^lease-[0-9]+$` — reject anything else, including empty, `.`,
    `..`, path separators, or anything with `/`). Joins
    `filepath.Join(leasesRoot, leaseID)`, resolves both `leasesRoot` and
    the joined path with `filepath.EvalSymlinks` (falling back gracefully
    if the target doesn't exist yet — only the existing parent needs to
    resolve), and requires the resolved target to have the resolved
    `leasesRoot` as a strict path-separator-bounded prefix (`root+"/"` is a
    prefix of `target`, not just a string prefix — `leasesRoot=/a/leases`
    must NOT accept `/a/leases-evil`) AND the target must NOT be equal to
    `leasesRoot` itself (never allow wiping the whole leases directory
    through this function — only per-lease subdirectories). Returns the
    validated absolute path or a typed error explaining exactly which
    check failed.
  - `DeleteLeaseDir(leasesRoot, leaseID string) error`: calls
    `ValidateLeasePath` first (no caller may skip it — this function does
    NOT accept a raw path parameter, only `leasesRoot`+`leaseID`, so there
    is no code path into deletion that bypasses validation), then
    `os.RemoveAll` on the validated path only. Missing path is not an
    error (idempotent). Every error is a typed code/message/fix triple
    (duplicate the local error-triple pattern from `internal/broker/errors.go`
    / `internal/provisioner/errors.go` — do not import `internal/ipc`).
- `internal/safety/devices.go` (new):
  - `IsSimurghManagedName(name string) bool`: the single source of truth
    for the regex `^simurgh-(clone|warm)\[.*\]$`, compiled once. Exported
    so M1.3's orphan scan and M2's prune planner can classify devices
    without duplicating the pattern.
  - A minimal `DeviceLister` interface this package depends on:
    `ListDevices(ctx context.Context) ([]Device, error)` where `Device`
    has at least `UDID, Name string`. Do not import `internal/provisioner`
    (that package depends on nothing from safety and should stay that
    way — safety defines its own tiny structurally-identical type or a
    minimal shared shape; a few duplicated fields is fine, an import cycle
    or a surprising cross-package dependency here is not).
  - A minimal `DeviceDeleter` interface: `Shutdown(ctx, udid string) error;
    Delete(ctx, udid string) error` (shutdown-then-delete; shutdown errors
    on an already-shutdown device should be tolerated/ignored by the real
    implementation, tested here via a fake).
  - `ValidateDeviceDeletion(ctx, lister DeviceLister, udid string,
    knownLeaseUDIDs map[string]bool) (Device, bool, error)`: queries
    `lister.ListDevices` (never trusts a caller-supplied name), finds the
    device by UDID (not found → typed error, not silently OK), checks
    `IsSimurghManagedName(device.Name)` (false → typed error, refuse), and
    returns the live `Device` plus a boolean `knownLease` (whether
    `knownLeaseUDIDs[udid]` was true) purely for audit/logging by the
    caller — this function performs NO deletion itself, it only validates
    and reports. Keep this pure/side-effect-free (beyond the read-only
    list call) so it's directly unit-testable as the roadmap's "prune plan
    never contains a non-simurgh-named device" property.
  - `DeleteSimulatorClone(ctx, lister DeviceLister, deleter DeviceDeleter,
    udid string, knownLeaseUDIDs map[string]bool) error`: calls
    `ValidateDeviceDeletion` first (again: no code path to `deleter.Delete`
    that skips validation — this is the only function in the package that
    actually deletes a device, and it always validates immediately before
    acting, no caching of a prior validation result across a time gap),
    then `deleter.Shutdown` (best-effort, ignore "already shutdown"-shaped
    errors) then `deleter.Delete`. Real `simctl` errors from `Delete`
    itself propagate as a typed error.
- `internal/safety/errors.go` (new) — typed errors: `PathOutsideLeasesRootError`,
  `InvalidLeaseIDError`, `DeviceNotManagedError` (name doesn't match
  pattern), `DeviceNotFoundError`, each with code/message/fix.
- `internal/safety/paths_test.go` — **adversarial property tests, not just
  happy-path**: use `testing/quick` (Go stdlib, no new dependency) to
  randomize `leaseID` strings including path separators, `..`, null bytes,
  unicode, empty, very long strings — assert `ValidateLeasePath` NEVER
  returns a path outside `leasesRoot` and NEVER panics. Plus a curated
  adversarial table covering, at minimum: `leaseID="../.."`,
  `leaseID="../../../etc"`, `leaseID="lease-1/../../evil"`,
  `leaseID=""`, `leaseID="."`, `leaseID="lease-1\x00evil"`, a symlink
  planted inside `leasesRoot` pointing outside it (create this for real in
  a `t.TempDir()` and confirm `ValidateLeasePath`/`DeleteLeaseDir` refuse
  to follow it out), and confirm `leasesRoot` itself can never be the
  resolved target (`leaseID` that resolves to exactly `leasesRoot`, e.g. via
  a crafted symlink, must be refused).
- `internal/safety/devices_test.go` — property/adversarial tests for
  `IsSimurghManagedName` against: real intended names (`simurgh-clone[x]`,
  `simurgh-warm[a:b:c]`), near-miss adversarial names (`Simurgh-clone[x]`
  wrong case, `simurgh-clone[x]evil` trailing garbage, `xsimurgh-clone[x]`
  leading garbage, `simurgh-cloney[x]`, `simurgh-clone(x)` wrong bracket,
  `simurgh-base[x]` — must be false, bases are never deletable through this
  path, matches M1.2's design), and confirm the regex is fully anchored
  (`^...$`, not `.*...*` — a table-driven test asserting both ends).
  `ValidateDeviceDeletion`/`DeleteSimulatorClone` tests against a fake
  `DeviceLister`/`DeviceDeleter`: managed name → validates/deletes;
  non-managed name (even if the UDID is in `knownLeaseUDIDs` — the known-
  lease set must NEVER override a failing name check) → refused, `Delete`
  never called on the fake; unknown UDID → refused; lister returning a
  DIFFERENT live name than what a stale caller might have expected →
  the live name is what's checked (simulate this explicitly).
- `internal/safety/integration_test.go` (new) — `//go:build darwin_sim`
  tagged, REAL simctl. **Hard requirement: every destructive operation in
  this test targets ONLY a throwaway device this test itself creates in
  the same run** (name it `simurgh-clone[test-safety:...]`, created via a
  small test-local raw `simctl create`+`rename`+`boot`-optional helper —
  do not import `internal/provisioner`, keep this test self-contained).
  Cases: (1) delete the test's own throwaway clone → succeeds, confirmed
  gone via `simctl list devices`; (2) attempt to delete the REAL
  `simurgh-base[iPhone 17 Pro:27.0]` device already present on this Mac
  from M1.2's prior runs (or create+leave a fresh `simurgh-base[...]` if
  none exists) → **must be refused** with `DeviceNotManagedError`, and
  confirm via `simctl list devices` afterward that it still exists,
  untouched; (3) attempt to delete a syntactically-plausible but
  nonexistent UDID → typed not-found error, no crash. For paths: use
  `t.TempDir()` as `leasesRoot` (never the real `~/.simurgh`), create a
  fake lease dir with files, delete it, confirm gone; attempt a
  traversal/symlink-escape against a real filesystem (not just the
  in-memory adversarial tests) and confirm nothing outside `t.TempDir()`
  is touched.
- `internal/safety/doc.go` — package comment: this is the only package
  permitted to delete; every other package must call into it.

Do not edit `internal/store`, `internal/ipc`, `internal/broker`,
`internal/provisioner`, `internal/watcher`, `internal/reaper`,
`internal/cli`, `cmd/simurgh`, CI config, or any doc other than
`docs/plans/orchestrator-state.md`.

## Explicitly out of scope

- Wiring safety into M1.3's reaper or M2's prune — those are separate,
  later packages that will import and call this one. This package only
  needs to exist and be correct in isolation.
- Any deletion target other than (a) a validated per-lease directory under
  an injected leases root, and (b) a single simulator device by UDID after
  live validation. No batch/glob deletion, no "delete everything matching
  a pattern" convenience function — every call site must name an exact
  target.
- Warm-template-specific logic beyond the shared `IsSimurghManagedName`
  check (M2 decides when a warm template becomes eligible for removal;
  this package only says whether a given name is *structurally* deletable
  at all).
- Config file reading, logging/audit-trail persistence (the `knownLease`
  boolean is returned to the caller to log; this package does not log or
  persist anything itself).

If implementing the required behavior turns out to need any of the above,
or if you find yourself tempted to add a "just this once" bypass of
`ValidateLeasePath`/`ValidateDeviceDeletion`, STOP and report back to the
orchestrator rather than proceeding — this is the one package in the
codebase where "I'll just make it work" is the wrong instinct.
