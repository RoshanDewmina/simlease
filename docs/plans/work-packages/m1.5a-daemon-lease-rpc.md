# M1.5a work package — daemon lease RPCs + reclaim-loop wiring

## Goal

Wire the broker/provisioner/watcher/reaper stack (all merged, all unit- and
`[mac]`-tested in isolation) into the running daemon: register the six
`lease.*` IPC methods so a client can actually acquire/renew/release/get/
list/wait over the socket, and glue `watcher.Run`'s decisions to
`broker.Reclaim` + `reaper.Reclaim`/`ScanOrphans` so reclamation actually
happens while the daemon runs. This was explicitly deferred out of M1.3 and
M1.2 — this package is where the "daemon event loop" finally exists.
M1.5b (a separate, later package) builds the CLI client commands on top of
these RPCs.

## Source requirements

- `docs/ARCHITECTURE.md:135-157` (§5 IPC protocol) — the exact wire shapes,
  quoted here so there is no ambiguity:
  ```
  → {"v":1,"id":"r1","method":"lease.acquire",
     "params":{"spec":{"platform":"iOS","model":"iPhone 17 Pro"},
               "labels":{"task":"add-paywall"},"ttl":"30m",
               "reuseIfExists":true,"wait":true,"releaseOnPIDExit":true,
               "owner":{"pid":4242,"agent":"claude-code"}}}
  ← {"v":1,"id":"r1","ok":true,"result":{"lease":{ ...Lease... }}}
  ← {"v":1,"id":"r1","ok":false,
     "error":{"code":"CAPACITY_QUEUED","queuePosition":2,
              "message":"2 leases ahead of you (capacity 3/3 active)",
              "fix":"simurgh status --queue   # or pass wait:true"}}
  ```
  `ttl`/`Timeouts.Inactivity`/`Timeouts.Hard` are wire strings parsed with
  `time.ParseDuration` (e.g. `"30m"`), not nanosecond integers. Methods:
  `lease.acquire|renew|release|get|list|wait`. This package does NOT
  implement `pool.status`, `warm.*`, `daemon.shutdown`, or `prune.*` — only
  the six `lease.*` methods plus the existing `daemon.ping`.
- `docs/ARCHITECTURE.md:248-255` (§10) — the reclaim loop: watcher ticks on
  an interval, decisions get applied via `broker.Reclaim` then
  `reaper.Reclaim`; reaper's orphan scan runs on its own (slower) interval
  and naturally respects the 10s post-start reconciliation window
  `internal/reaper` already enforces internally — this package does not
  need to re-implement that gate, just call `ScanOrphans` and not treat an
  empty pre-window result as "no orphans exist."
- `internal/broker`, `internal/provisioner`, `internal/watcher`,
  `internal/reaper`, `internal/safety`, `internal/ipc` (all existing,
  mostly read-only for this package except the two additive edits below) —
  read `internal/broker/broker.go`'s full public API,
  `internal/provisioner/provisioner.go` (for constructing the real
  `execSimctlClient`... note: M1.2's real simctl client type is currently
  unexported/internal to `internal/provisioner` — check whether it needs a
  small exported constructor added, e.g. `provisioner.NewRealSimctlClient()`
  or similar, so `cmd/simurgh` can build a real `*provisioner.Provisioner`
  without reaching into unexported internals; if so, that is a third
  small permitted additive edit, to `internal/provisioner` only, adding an
  exported constructor with zero behavior change).
- `docs/REVIEW_STANDARDS.md` — error triple at every boundary; this package
  is the first place broker's local `*broker.Error`/typed errors must be
  translated into `internal/ipc`'s `*ipc.Error` wire shape — get that
  mapping right and complete (every broker error type needs a mapping, not
  just the happy path).

## Exact write-set

- `internal/ipc/server.go` — ONE additive change:
  `func (s *Server) RegisterHandler(method string, h HandlerFunc)`
  (mutex-guarded like the rest of `Server`'s state, or safe to call only
  before `Serve` starts — document which and enforce it if it matters:
  since handlers map access during `Serve` is read-only per-connection
  dispatch and registration happens once at startup before `Serve` is
  called, a simple unguarded map write is fine AS LONG AS registration is
  documented as "call before `Serve`, never concurrently with it" — pick
  the safer of (a) mutex-guard it anyway (cheap, removes the caller
  discipline requirement) or (b) document+enforce the pre-Serve-only
  contract; prefer (a) unless it's meaningfully more code). Do not change
  `NewServer`'s existing `daemon.ping` registration or any other behavior.
- `internal/broker/types.go` — ONE additive change: JSON struct tags on
  every field of `Lease`, `Owner`, `DeviceSpec`, `Device`, `Connection`,
  `Timeouts`, `AcquireRequest`, `ListFilter`, matching the architecture's
  wire field names exactly (`platform`, `model`, `runtime`, `pid`, `ppid`,
  `agent`, `sessionId`, `udid`, `name`, `cloneOf`, `booted`, `transport`,
  `id`, `state`, `owner`, `labels`, `spec`, `device`, `connection`,
  `acquiredAt`, `expiresAt`, `ttl`, `heartbeatAt`, `timeouts`,
  `releaseOnPidExit`, `reuseIfExists`, `wait`, `inactivity`, `hard`, etc. —
  use your best judgment for exact casing consistency (camelCase
  throughout, matching the `queuePosition`/`reuseIfExists` casing already
  visible in the architecture's own JSON examples) and note any field you
  had to invent a name for since the doc doesn't spell out every one.
  `time.Duration` fields (`TTL`, `Timeouts.Inactivity`, `Timeouts.Hard`)
  need custom `MarshalJSON`/`UnmarshalJSON` (or a small wrapper type) so
  they serialize as duration strings (`"30m"`) per the wire example, not
  as raw nanosecond integers — add this without changing how any existing
  broker/provisioner/watcher/reaper code constructs or reads these fields
  in Go (they still use plain `time.Duration` internally; only the JSON
  boundary changes). **Do not change any non-JSON-tag behavior in this
  file.** Re-run `internal/broker`'s full existing test suite unchanged
  (it must still pass byte-for-byte the same assertions) to prove this.
- `internal/provisioner/provisioner.go` or a new
  `internal/provisioner/simctl_real.go` — if the real `execSimctlClient` (or
  equivalent concrete `SimctlClient` implementation used by M1.2's live
  integration test) is not already exported, add a minimal exported
  constructor (e.g. `func NewExecSimctlClient() SimctlClient`) with zero
  behavior change — just making the existing real implementation
  reachable from outside the package. If it's already exported, skip this
  file entirely and say so in your report.
- `internal/daemon/daemon.go` (new package) — the integration glue:
  - `type Deps struct { Broker *broker.Broker; Reaper *reaper.Reaper;
    LeasesRoot string }` (constructed by the caller in `cmd/simurgh`, this
    package does not itself construct a `Broker`/`Provisioner`/`Reaper` —
    keep this package about wiring/translation, not object construction,
    so it stays unit-testable against fakes/small brokers).
  - `RegisterLeaseHandlers(server *ipc.Server, deps Deps)`: registers
    `lease.acquire`, `lease.renew`, `lease.release`, `lease.get`,
    `lease.list`, `lease.wait` via `server.RegisterHandler`. Each handler:
    decodes `req.Params` (`json.RawMessage`) into a small per-method
    request DTO (do not reuse `broker.AcquireRequest` directly as the wire
    DTO if its Go field names/types don't cleanly match the wire shape —
    an explicit small DTO with its own JSON tags, converted to
    `broker.AcquireRequest` in code, is clearer and decouples the wire
    contract from broker's internal Go shape), calls the matching
    `Broker` method, and on success marshals `{"lease": <Lease>}` (matching
    the architecture's exact envelope, note the "lease" wrapper key) as
    the result; `lease.list` returns `{"leases": [...]}` similarly. On
    error, maps the broker's typed error to an `*ipc.Error` — write a
    dedicated `brokerErrorToIPC(err error) *ipc.Error` covering every
    exported broker error type (`LeaseNotFoundError`, `InvalidStateError`,
    `CapacityQueuedError` — include `QueuePosition` in the mapped
    `ipc.Error`, `internal/ipc.Error` needs a `QueuePosition *int` field if
    it doesn't already have one; check and add it additively if missing —
    and `ProvisionFailedError`), plus a fallback for any unmapped error
    (internal/unexpected → a generic `INTERNAL` code, never leak a raw Go
    error string as the `code` field).
  - `type ReclaimLoop struct { ... }` with a `Run(ctx context.Context,
    watchInterval, orphanScanInterval time.Duration)` method: runs
    `watcher.Run` internally (or an equivalent tick loop) with a callback
    that, for each `ReclaimDecision`, calls `deps.Broker.Reclaim(ctx,
    leaseID)` then, on success, `deps.Reaper.Reclaim(ctx, lease)` — log
    (via a simple injected `Logger func(format string, args ...any)`  seam,
    default `log.Printf`, no new logging dependency) any error from either
    step rather than crashing the loop; one failed reclaim must not stop
    the loop from processing the next tick or the next decision. On a
    slower separate ticker, calls `deps.Reaper.ScanOrphans` with the
    broker's current known-UDID set (derive this from `deps.Broker.List
    (ListFilter{})`'s `Device.UDID`s for non-terminal leases) and logs
    (does not delete) any orphan UDIDs found — actually reclaiming
    discovered orphans automatically is a **judgment call left to you**:
    if you choose to auto-reclaim them, it MUST go through
    `safety.DeleteSimulatorClone` (already how `Reaper.Reclaim` calls it)
    with the same live-revalidation guarantee, never a shortcut; if you
    choose to only log-and-report for now (deferring auto-reclaim of
    orphans to a future CLI `prune --apply` command per the roadmap's own
    M2.3 "prune + doctor extensions" milestone), that is equally
    acceptable and arguably safer for a first cut — pick one, document
    the choice clearly in code comments and your final report, and make
    sure whichever you pick has a test proving it.
  - `internal/daemon/doc.go` — package comment.
- `internal/daemon/daemon_test.go` — unit tests against a real in-memory
  `*broker.Broker` (constructed with a fake `Provisioner`, per M1.1's own
  test patterns — no real simctl needed here) and a fake `ipc.Server`-like
  harness (or, simpler: test the handler functions directly by calling
  them with hand-built `ipc.Request`s and asserting the decoded
  `ipc.Response`, without needing a real socket) covering: acquire →
  correct JSON lease result; acquire hitting capacity → `CAPACITY_QUEUED`
  error with `queuePosition` present in the wire JSON; get/list/renew/
  release/wait each round-trip correctly; an unknown lease ID on any
  method → `LEASE_NOT_FOUND`; the reclaim loop actually calls
  `Broker.Reclaim` then `Reaper.Reclaim` when the watcher decides to
  reclaim (fake `IsProcessAlive` returning false, as `internal/watcher`'s
  own tests already do), and one failing reclaim doesn't block a
  subsequent tick's decisions.
- `cmd/simurgh/daemon.go` — wire it: after `ipc.Listen`/`ipc.NewServer`,
  construct `*provisioner.Provisioner` (real client), `*broker.Broker`
  (real `Provisioner`, real capacity formula seams — reuse whatever
  `DefaultSocketPath`-style helpers already exist for resolving
  `LeasesRoot` under `~/.simurgh/leases`, honoring `$SIMURGH_HOME` the same
  way `DefaultSocketPath` already does), `*reaper.Reaper` (real
  `DeviceLister`/`DeviceDeleter` — check whether `internal/provisioner`'s
  real client also satisfies `internal/safety`'s `DeviceLister`/
  `DeviceDeleter` interfaces directly, or needs a small adapter; either is
  fine, keep it minimal), call `internal/daemon.RegisterLeaseHandlers`,
  start a `ReclaimLoop` goroutine (context-cancelled alongside the
  existing SIGINT/SIGTERM shutdown context already in this file — do not
  change the existing shutdown signal handling, just hang the new
  goroutine off the same `ctx`), then call `srv.Serve(ctx)` as before.
  Pick reasonable default intervals (e.g. watch every 5–10s, orphan scan
  every few minutes) and note them in a comment; these are not
  user-configurable yet (config.yaml reading is out of scope, same as
  M1.1/M1.2's existing scope notes).

Do not edit `internal/store`, `internal/cli`, `internal/watcher`,

## Explicitly out of scope

- CLI client commands (`simurgh acquire` etc.) — M1.5b, a separate later
  package, consumes these RPCs.
- `pool.status`, `warm.*`, `daemon.shutdown`, `prune.*` IPC methods.
- Config file reading, LaunchAgent/`daemon install`.
- Auto-reclaiming discovered orphans is optional per the judgment call
  above; if deferred, it is explicitly not a gap to "fix" in this package
  — note it and move on.
- Any change to `internal/watcher`'s or `internal/reaper`'s existing
  public API beyond calling their existing exported functions/methods.

   note in your report that full end-to-end reclaim-to-deletion was not
   exercised live and why. Kill the daemon and clean up any devices your
   manual test created (do not leave real clones behind — confirm via
   `xcrun simctl list devices | grep -i simurgh` before/after showing only
   the pre-existing `simurgh-base[...]`).

Return verbatim output, changed files, diff stat, and your decision +
reasoning on the auto-reclaim-orphans judgment call. Do not commit.

## Risk class

`low` for the RPC/wiring code itself (translation and glue, no new
destructive operations — every delete still goes exclusively through
`internal/safety` via the existing `reaper.Reclaim`). However this is the
first package where a REAL client can trigger REAL device creation over
the network-equivalent (local socket) surface, and the first place
`ReclaimLoop` can call real deletion automatically/unattended while the
daemon runs — read the wiring code closely for anything that could call
`Reaper.Reclaim`/`ScanOrphans`-driven deletion on the wrong lease/UDID due
to a translation bug (e.g. wrong lease passed to `Reaper.Reclaim` after a
decision). Standard review pipeline (fresh review), but the orchestrator
should personally spot-check the `ReclaimLoop` wiring specifically before
merge given what it's capable of doing unattended.
