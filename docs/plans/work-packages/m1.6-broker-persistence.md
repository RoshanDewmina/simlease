# M1.6 work package — broker persistence + startup reconciliation

## Goal

Close the one M1 `[mac]` GATE sub-scenario that's still open: "daemon
SIGKILL mid-provision → restart reconciles with zero orphans and zero
non-simurgh deletions." Wire `internal/broker` to persist its lease map
through `internal/store`'s journal on every state-mutating operation, and
implement real `internal/reaper.Reconcile` so a freshly-started daemon can
rehydrate what it owned before a crash and correctly classify any
`simurgh-clone[...]` device it doesn't recognize as an orphan (log-only,
same policy M1.5a already established — this package does not change
that policy, only makes orphan detection survive a restart instead of
only working within a single process's lifetime).

## Source requirements

- `docs/ARCHITECTURE.md:88-92` (§3) — "Store: `state.json`, atomic
  rewrite... On daemon start: load journal → reconcile against `simctl
  list -j` reality (devices are truth for existence; journal is truth for
  ownership) → reap inconsistencies." This is the exact algorithm to
  implement: journal for ownership, live `simctl` scan for existence,
  reconcile the two.
- `docs/ARCHITECTURE.md:107-133` (§4) — "Reclamation is idempotent and
  crash-safe: reaper re-derives work from (journal ∪ device-name scan), so
  a daemon crash mid-cleanup self-heals on restart."
- `docs/ROADMAP.md`'s M1.6 entry (added 2026-07-13) and the M1 GATE
  `[mac]` text this closes.
- `internal/store/store.go` (existing) — `State{SchemaVersion int}`, doc
  comment: "lease/broker fields arrive in later milestones." This is that
  milestone. **Keep `store` fully decoupled from `broker`'s types** (no
  import of `internal/broker` into `internal/store` — that would create a
  cycle, since `broker` needs to import `store` to call `Save`/`Load`).
  Add exactly one new field: `Leases json.RawMessage \`json:"leases,
  omitempty"\`` to `State`. `SchemaVersion` stays `1` (this is an additive
  field, not a breaking schema change) — do not bump it. Existing M0.3
  tests (`TestLoadMissingJournalReturnsEmptySchemaV1` etc.) must still
  pass unchanged; add new tests for the `Leases` field round-tripping
  opaque JSON without `store` ever interpreting its contents.
- `internal/broker` (existing) — read the full current `broker.go`,
  `types.go` (JSON tags already exist from M1.5a, so `json.Marshal(b.
  leases)` already produces a sensible wire/storage shape — reuse it,
  do not invent a second serialization format).
- `internal/reaper/reaper.go` (existing) — `Reconcile` is currently a
  documented no-op stub with a `TODO(m1.x-store)` comment. This package
  is that TODO's payoff. `ScanOrphans` already exists and already respects
  the 10s reconciliation window — reuse it, do not reimplement window
  logic.

## Exact write-set

- `internal/store/store.go`, `internal/store/store_test.go` — add
  `Leases json.RawMessage \`json:"leases,omitempty"\`` to `State`. No
  other change to this file's logic (atomic-write mechanics, permission
  bits, corrupt-JSON handling, schema-version check all stay exactly as
  they are). New test: save a `State` with a non-trivial `Leases` payload,
  load it back, confirm byte-for-byte (or semantically-equal JSON)
  round-trip, and confirm `store` never unmarshals `Leases`'s *contents*
  (it's opaque `json.RawMessage` all the way through).
- `internal/broker/broker.go`, `internal/broker/broker_test.go` — additive
  only, no change to any existing method's observable behavior for the
  in-memory-only (no `Store` configured) case, which is what every
  existing test exercises:
  - `BrokerOptions` gains an optional `Store *store.Store` field (nil by
    default — persistence is opt-in; existing tests that construct
    `Broker` without a store must keep passing unchanged, proving
    persistence is additive not required).
  - A private `persistLocked()` method, called at the END of every
    state-mutating method (`Acquire`'s transition points inside
    `finishProvision`, `Renew`, `Release`, `Reclaim`) **while still
    holding `b.mu`**, immediately before that method's own unlock —
    correctness over performance for v0: persisting under the same lock
    that serializes all state mutations guarantees journal writes apply
    in the same order as the in-memory transitions, with no possible
    reordering/lost-update race between two concurrent mutations. If
    `b.store == nil`, `persistLocked` is a no-op (zero cost when
    persistence isn't configured). On a `store.Save` error, log via a
    small injected `Logger func(format string, args ...any)` seam
    (default `log.Printf`, matching `daemon.ReclaimLoop`'s existing
    pattern) — a persistence failure must NOT fail or roll back the
    in-memory state transition itself (the in-memory broker is still the
    source of truth for the running process; the journal is best-effort
    durability for the *next* process, not a transactional requirement
    for *this* one).
  - `persistLocked` marshals `b.leases` (the full map) to JSON and calls
    `b.store.Save(store.State{SchemaVersion: store.SchemaVersion, Leases:
    <marshaled>})`.
  - `func (b *Broker) Rehydrate() error`: called once at construction time
    (or immediately after `New`, your choice — document whichever) when
    `opts.Store != nil`. Loads the journal via `store.Load()`, unmarshals
    `Leases` into `map[string]*Lease` if present (empty/missing `Leases`
    field is not an error — a fresh/never-persisted journal), and for
    each rehydrated lease applies this **startup normalization** (a crash
    can only have interrupted something mid-flight, never lost the
    fact that it existed):
    - `QUEUED` → keep as `QUEUED`, re-enter it into the correct
      per-spec-key FIFO queue in the same relative order the journal
      preserves (map iteration order isn't stable — if you need FIFO
      order preserved across restart, `Leases` may need to serialize as
      an ordered slice instead of a map, OR you accept that queue order
      is not guaranteed to survive a crash for v0 and document that
      explicitly as a known limitation — pick one and state your choice
      clearly in the code and your report, this is a real design
      decision the spec is deliberately leaving to you rather than
      over-specifying).
    - `PROVISIONING` → **cannot be resumed** (no goroutine is running
      `finishProvision` for it anymore; the process that was doing that
      is dead). Transition to `FAILED` on rehydration with a clear reason
      recorded (reuse the existing `ProvisionFailedError`-shaped
      handling/logging pattern if convenient, or just log it — this
      lease's eventual device, if `simctl` partially created one before
      the crash, becomes visible to the orphan scan below since it won't
      be in the rehydrated ACTIVE set).
    - `ACTIVE` → keep as `ACTIVE` as-is, including its `Device`. This is
      the "restart reconciles... zero orphans" case: a real booted clone
      that legitimately belongs to a real lease must NOT be treated as an
      orphan just because the daemon restarted.
    - `RELEASED`/`CANCELLED`/`FAILED`/`RECLAIMED` → keep as-is (terminal,
      informational; they don't re-enter any active bookkeeping like
      capacity counts or queues).
    Capacity bookkeeping (`slotCountLocked`) already derives from
    `b.leases`' states, so rehydrating leases into the map is sufficient
    to make capacity accounting correct post-restart — no separate
    counter to rehydrate.
  - `func (b *Broker) KnownDeviceUDIDs() map[string]bool`: returns the
    UDIDs of all non-terminal (queued/provisioning/active) leases' known
    devices — same shape `internal/daemon`'s existing
    `knownNonTerminalUDIDs` helper already computes from outside the
    package; expose it as a proper `Broker` method so `internal/reaper`
    doesn't need reflection-adjacent access and `internal/daemon`'s
    existing helper can be simplified to just call this (update
    `internal/daemon` to call the new method **only if** it's a trivial,
    behavior-preserving simplification — do not restructure
    `internal/daemon` beyond that one call site).
- `internal/reaper/reaper.go`, `internal/reaper/reaper_test.go` — replace
  the no-op `Reconcile` stub:
  - `func (r *Reaper) Reconcile(ctx context.Context, knownDeviceUDIDs map[
    string]bool) ([]string, error)`: **respects the same 10s
    reconciliation window `ScanOrphans` already enforces** (returns
    `(nil, nil)` immediately if called too early — reuse `ScanOrphans`
    internally rather than duplicating the window check; `Reconcile` can
    literally just be a thin documented wrapper around `ScanOrphans` now
    that the "known" set is being computed correctly cross-process via
    the broker's rehydrated state, OR keep them as two distinct exported
    methods if that reads clearer — your call, but do not implement the
    window check twice). Returns the same orphan-UDID list shape
    `ScanOrphans` already returns; still performs **no deletion** — the
    log-only policy is unchanged, only the source of "known" UDIDs is now
    crash-durable instead of same-process-only.
  - Update the doc comment to remove the "TODO(m1.x-store)" — this is
    that package, landing.
- `cmd/simurgh/daemon.go` — wire it: construct the `broker.New` call with
  `Store: store.New(<journal path — reuse whatever path convention
  DefaultSocketPath/DefaultLeasesRoot already establish, e.g.
  filepath.Join(home, "state.json") honoring $SIMURGH_HOME the same way>)`,
  call `Rehydrate()` right after construction and before `ipc.NewServer`/
  `Serve` starts accepting connections (so no client can observe a
  half-initialized broker), then after the `ReclaimLoop` starts, have its
  first orphan-scan-equivalent tick call `Reconcile` with
  `brk.KnownDeviceUDIDs()` instead of (or in addition to) `ScanOrphans` —
  simplest correct approach: since `Reconcile` and `ScanOrphans` now do
  the same thing with the same window logic, you may consolidate
  `ReclaimLoop`'s orphan-scan ticker to call `Reconcile` instead of
  `ScanOrphans` directly, since `Reconcile`'s known-set is now the
  correct, crash-durable one — make this simplification if it's clean,
  otherwise call both are equivalent and either is acceptable, just don't
  leave two subtly-different behaviors where one is obviously stale.
- `internal/store/doc.go`, `internal/broker/doc.go`, `internal/reaper/
  doc.go` — update the scope-boundary comments that currently say
  persistence "doesn't exist yet" / "is a separate, later package" — this
  is that package, update them to say so.

Do not edit `internal/ipc`, `internal/provisioner`, `internal/safety`,
`internal/watcher`, `internal/cli`, CI config, or any doc other than
`docs/plans/orchestrator-state.md`. The permitted edits are exactly:
`internal/store` (additive field only), `internal/broker` (additive
Store/Rehydrate/KnownDeviceUDIDs), `internal/reaper` (Reconcile), `internal/
daemon` (the one call-site simplification, if made), `cmd/simurgh/daemon.go`
(wiring).

## Explicitly out of scope

- Auto-reclaiming orphans discovered via `Reconcile` — still log-only,
  same as `ScanOrphans` today. Do not change this policy.
- Any change to the on-disk `state.json` **format** beyond the additive
  `Leases` field — no schema version bump, no migration logic.
- Config file reading, warm templates, isolation env — M2 territory.
- Making `Store` non-optional or changing any existing `Broker` test that
  constructs a store-less `Broker` — persistence stays additive.

If implementing the required behavior turns out to need any of the above,
stop and report back to the orchestrator rather than expanding scope.

## Risk class

`low` for the code itself (no new destructive operation — this package
only reads/writes `state.json` via the already-safe `internal/store`
atomic-write mechanics, and calls the already-reviewed, log-only
`ScanOrphans`/`Reconcile`). However this is the second-most-central
package after `internal/broker` itself (every other package's correctness
assumption — "the broker's in-memory state is authoritative" — now has a
crash/restart edge case bolted on), so the orchestrator should personally
verify the rehydration logic (especially the PROVISIONING→FAILED
normalization and that ACTIVE leases are never mistaken for orphans)
rather than rely solely on a subagent review.
