# M2.1 work package — isolation environment (per-lease dirs, env/flag emission, exec)

## Goal

Implement `internal/isolator`: per-lease isolated directories
(DerivedData/ModuleCache/SwiftPM/Results/tmp), the env-var + xcodebuild-flag
emission matrix (VibeChard's proven seven-resource pattern, attribution
required), `lease.json` snapshot writing, and the `simurgh env <id>` /
`simurgh exec <id> -- <cmd>` CLI commands. Also scaffolds the minimal
fixture iOS app M2's own `[mac]` GATE needs to prove isolation for real
(concurrent builds against the SAME scheme must not collide).

## Exact write-set

- `test/fixtures/SampleApp/` (new) — a minimal, real, buildable iOS app
  target the GATE above can run against. Use `xcodegen` (already
  installed on this Mac, confirmed via `xcodegen --version`) with a small
  `project.yml`: one iOS app target named `SampleApp`, minimal
  `SwiftUI`/`UIKit` "Hello World" source (a single trivial Swift file is
  enough — this exists purely to prove build isolation, not to be a real
  app), bundle id `dev.simurgh.fixtures.sampleapp`, deployment target
  matching the installed iOS 27.0 runtime, no external SwiftPM
  dependencies needed for v0 (a bare app target is sufficient to exercise
  `-derivedDataPath`; if you want to also prove `-clonedSourcePackagesDirPath`
  isolation, add exactly one trivial local-or-tiny-public SwiftPM
  dependency — your call, keep it small and fast to resolve). Run
  `xcodegen generate` to produce the `.xcodeproj`, commit the generated
  project (this is a test fixture, not app source — committing the
  generated `.xcodeproj` is correct here so the GATE doesn't require
  `xcodegen` as a test-time dependency). Confirm
  `xcodebuild -project test/fixtures/SampleApp/SampleApp.xcodeproj -scheme
  SampleApp -destination "platform=iOS Simulator,name=iPhone 17 Pro"
  -derivedDataPath /tmp/probe-dd build` succeeds standalone before wiring
  anything else — this is your own sanity check, not part of the package's
  return-value tests.
- `internal/isolator/isolator.go` (new):
  - `type LeaseDirs struct { Root, DerivedData, ModuleCache, SwiftPM,
    Results, Tmp string }`
  - `func EnsureLeaseDir(leasesRoot, leaseID string) (LeaseDirs, error)`:
    creates all five subdirectories (mode 0700, idempotent — `MkdirAll`)
    under `filepath.Join(leasesRoot, leaseID)`. Injected `leasesRoot`
    only, same convention as every other package (`internal/store`,
    `internal/ipc`, `internal/provisioner`) — never resolves `~/.simurgh`
    itself.
  - `func BuildEnv(dirs LeaseDirs, leaseID, udid string) broker.
    IsolationEnv`: **pure, no side effects** — computes the exact `Env`
    map, `XcodebuildFlags` slice, and `ShellSnippet` string from the
    ARCHITECTURE §7 example above, byte-for-byte matching field names
    (`SIMURGH_LEASE_ID`, `SIMURGH_UDID`, `SIMURGH_DERIVED_DATA`,
    `CLANG_MODULE_CACHE_PATH`, `SIMURGH_RESULT_BUNDLE_DIR`,
    `SIMURGH_SWIFTPM_DIR`; flags `-derivedDataPath`,
    `-clonedSourcePackagesDirPath`, `-destination`). This function imports
    `internal/broker` for the `IsolationEnv`/`Device` types (one-directional
    dependency, same pattern as `internal/provisioner`). **Attribution
    comment here**, at the flag-matrix definition site, per the reuse
    rule: cite VibeChard + Apache-2.0.
  - `func AllocateResultBundlePath(dirs LeaseDirs, now func() time.Time)
    string`: returns `Results/run-<unix-nano-or-RFC3339-safe-timestamp>.
    xcresult` — a fresh path every call (this is the "requires a new path
    per run" discipline). Injected clock for testability.
  - `func WriteLeaseSnapshot(dirs LeaseDirs, lease broker.Lease, env
    broker.IsolationEnv) error`: writes `<dirs.Root>/lease.json` — the
    full lease record plus its computed env, atomic-write style (temp
    file + rename, mirroring `internal/store`'s existing pattern — do not
    reimplement atomic-write from scratch if a small shared helper makes
    sense, but do not create a new cross-package dependency just for this;
    a few duplicated lines of temp+rename here is fine and consistent
    with this codebase's existing "duplicate small helpers rather than
    force a shared-package dependency" pattern, e.g. `internal/broker/
    errors.go`'s comment about duplicating rather than importing
    `internal/ipc`).
- `internal/isolator/isolator_test.go` — `EnsureLeaseDir` creates exactly
  the five expected subdirs, idempotent on a second call; `BuildEnv`
  produces the exact field names/values from the architecture example
  (a golden-ish table test); `AllocateResultBundlePath` returns a
  different path on each call (injected clock advancing); `WriteLeaseSnapshot`
  round-trips (write then read back the JSON, confirm shape).
- `internal/isolator/doc.go` — package comment + the VibeChard attribution.
- `internal/daemon/daemon.go` — additive wiring only: after a successful
  `Broker.Acquire` reaches `ACTIVE` (i.e. `lease.Device != nil`) in the
  `acquire` handler, call `isolator.EnsureLeaseDir` +
  `isolator.BuildEnv` + `isolator.WriteLeaseSnapshot`, and include the
  computed `IsolationEnv` in the WIRE response (extend
  `marshalLeaseResult`'s output to include the `env`/`xcodebuildFlags`/
  `shellSnippet` fields already declared on `broker.Lease.Env` — these
  fields exist and have JSON tags from M1.5a but are always empty today
  since nothing populates them; this package is what populates them, in
  the wire response only — **do not store computed env back into the
  broker's own in-memory/persisted `Lease.Env`** field via any new broker
  method; keep isolator's output purely a response-shaping concern in the
  daemon handler layer, recomputed fresh on every `get`/`list`/`wait`
  response the same way, since it's a pure function of already-known
  data (`LeasesRoot`, lease ID, `Device.UDID`) — cheaper and simpler than
  threading a new broker mutation through persistence). Apply the same
  "compute env in the wire response when the lease has a Device" treatment
  consistently across `acquire`, `get`, `list`, and `wait` handlers so a
  client always sees `env` populated for any ACTIVE lease, not just at
  acquire time. `EnsureLeaseDir`/`WriteLeaseSnapshot` (side-effecting) only
  need to run ONCE per lease — do it in `acquire`'s handler only, not on
  every subsequent `get`/`list` (which only need the pure `BuildEnv`
  computation for the response, no filesystem writes).
- `cmd/simurgh/env.go` (new):
  - `simurgh env <lease-id>`: calls `lease.get`, if the lease has a
    `Device` (ACTIVE with a real UDID), prints the `shellSnippet`-style
    eval-able `export KEY=value` lines for every entry in `env`
    (one per line, shell-quoted) to stdout. No `--json` needed here per
    the architecture's CLI surface (it's already eval-oriented output);
    if you want to also support `--json` for consistency with the rest of
    the CLI, that's fine, just keep the default plain-export format
    working since `eval "$(simurgh env <id>)"` is the documented UX.
    No-device/not-ACTIVE → the daemon's own typed error surfaces normally
    (reuse `exitCodeForIPCError`), no special-casing needed here.
  - `simurgh exec <lease-id> -- <cmd...>`: calls `lease.get`, builds the
    env (from the wire response), detects whether `cmd` looks like an
    `xcodebuild ... test ...`/`test-without-building` invocation (a
    simple substring/arg-scan heuristic is fine for v0 — don't
    over-engineer flag parsing) and if so allocates+injects
    `-resultBundlePath <fresh path>` via `isolator.AllocateResultBundlePath`
    on top of the base env/flags (client-side allocation is fine — the
    daemon doesn't need to track result-bundle paths). Runs `cmd` via
    `exec.CommandContext` with `Env: append(os.Environ(), <lease env as
    KEY=VALUE pairs>...)`, `Stdout`/`Stderr` wired to the CLI's own
    stdout/stderr, and exits with the child process's real exit code
    (not the 0/2/3/4/5 IPC contract — `exec` is a pass-through, its exit
    code IS the child's).
- `cmd/simurgh/main.go` — wire `env` and `exec` subcommands.

Do not edit `internal/store`, `internal/ipc`, `internal/broker` (beyond
nothing — this package does not touch broker at all, only imports its
types), `internal/provisioner`, `internal/watcher`, `internal/reaper`,
`internal/safety`, `internal/cli`, CI config, or any doc other than
`docs/plans/orchestrator-state.md`.

## Explicitly out of scope

- The PATH shim (auto-injecting flags into any bare `xcodebuild` call) —
  explicitly v0.1 per the architecture doc, do not build it.
- Warm templates (M2.2) and prune (M2.3).
- Storing computed `IsolationEnv` back onto the broker's persisted `Lease`
  — recompute fresh on every response instead (see the wiring note
  above for why).
- Any change to `SampleApp`'s actual app behavior beyond what's needed to
  make it buildable — it exists to be built, not to do anything.

## Risk class

`low` — no destructive operation (this package only creates directories
and writes files under the lease's own dir, never deletes anything itself;
lease-dir deletion remains exclusively M1.4 safety's `DeleteLeaseDir` via
the reaper, already reviewed and unchanged by this package). Standard
review pipeline.
