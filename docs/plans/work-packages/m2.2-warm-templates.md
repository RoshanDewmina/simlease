# M2.2 work package — warm templates

## Goal

Implement `simurgh warm create|list|remove`, thread a clone-from-warm path
into `internal/provisioner.Provision` (prefer an existing
`simurgh-warm[<model>:<runtime>]` device as the clone source over the plain
`simurgh-base[...]` when one matches spec — cuts clone+boot latency), and
exclude warm templates from the reaper's orphan scan (they're a distinct,
deliberately-persistent category, never a lease-owned or orphaned clone).

## Source requirements

- `docs/ARCHITECTURE.md:159-173` (§6), quoted: "Warm templates (VibeChard
  pattern): a primed, shut-down device named
  `simurgh-warm[<model>:<runtime>]` used as the clone source — cuts
  clone+boot latency substantially. `simurgh warm create|list|remove`;
  reaper never touches warm templates; the *name pattern is the source of
  truth* for what Simurgh owns (survives journal loss). Boot-on-demand v0;
  optional warm *pool* (pre-booted clones) is v1." — a **pool** of
  pre-booted spare clones is explicitly v1, out of scope here; v0 is: one
  warm template device exists (shutdown) per (model, runtime) you choose
  to prime, and `Provision` clones from it instead of the base when
  present.
- `docs/ROADMAP.md`'s M2.2 line: "`warm create|list|remove`,
  clone-from-warm path in provisioner, reaper exclusion, name-as-truth."
  M2 `[mac]` GATE: "warm template cuts acquire→Booted latency ≥50% vs cold
  (record numbers)" — this package's live check must record and report
  actual before/after timings, not just assert a boolean pass.
- `internal/safety/devices.go` (existing, read carefully) —
  `managedNamePattern = ^simurgh-(clone|warm)\[.*\]$` and
  `IsSimurghManagedName` already treat `simurgh-warm[...]` as a
  structurally deletable name — `warm remove` can and should reuse the
  EXISTING, already-reviewed `safety.DeleteSimulatorClone` directly. **Do
  not add a new deletion primitive.** What's missing is the reverse: a way
  to tell the reaper's orphan scan "this managed name is a warm template,
  never an orphan, skip it" — add exactly one new small exported function,
  `IsWarmTemplateName(name string) bool` (anchored `^simurgh-warm\[.*\]$`),
  alongside the existing `IsSimurghManagedName`, so `internal/reaper` can
  distinguish the two without duplicating regex logic.
- `internal/provisioner/provisioner.go` (existing, read carefully) — the
  current `ensureBaseDevice` (list-then-create, already race-safe via the
  per-`(model,runtime)` lock from the M1.2 review fix) is the function to
  extend, not replace: before falling back to "find or create
  `simurgh-base[...]`", first check for an existing
  `simurgh-warm[<model>:<runtime>]` device via the same `ListDevices`
  call already being made, and if found, clone from that UDID instead of
  the base UDID. The per-`(model,runtime)` lock (`lockForBase`) already
  serializes this whole check — reuse it, don't add a second lock. If no
  warm template exists, fall back to the existing base-device behavior
  unchanged (byte-for-byte — existing `internal/provisioner` tests for the
  no-warm-template case must keep passing unmodified).
- `internal/reaper/reaper.go` (existing) — `ScanOrphans` currently treats
  ANY `IsSimurghManagedName`-matching device not in `knownLeaseUDIDs` as
  an orphan candidate. Since a warm template is never a lease-owned UDID
  (leases clone FROM it, they don't share its identity), it would
  currently be incorrectly logged as an "orphan" forever. Fix: skip any
  device where `safety.IsWarmTemplateName(device.Name)` is true, before
  the `knownLeaseUDIDs` check.

## Exact write-set

- `internal/safety/devices.go`, `internal/safety/devices_test.go` — add
  `IsWarmTemplateName(name string) bool` (anchored `^simurgh-warm\[.*\]$`).
  Table-driven tests: matches `simurgh-warm[iPhone 17 Pro:27.0]`, does NOT
  match `simurgh-clone[...]` or `simurgh-base[...]` or near-miss
  adversarial variants (reuse the same adversarial-naming discipline
  `TestIsSimurghManagedName`'s table already established — case
  sensitivity, trailing/leading garbage, wrong brackets). **This is the
  only permitted edit to `internal/safety`** — do not touch
  `paths.go`/`errors.go`/the existing deletion functions at all.
- `internal/provisioner/warm.go` (new) — the warm-specific simctl surface,
  reusing the existing `SimctlClient` interface (do not add new interface
  methods if `Clone`/`Rename`/`Boot`/`WaitBooted`/`ListDevices`/`Create`
  already cover what's needed — check before adding anything to the
  interface; a warm template's lifecycle is create→boot→wait→**shutdown**,
  so if `SimctlClient` has no `Shutdown` method yet, add exactly one
  method to the interface plus its real `execSimctlClient`/`NewExecClient`
  implementation, mirroring `internal/safety.DeviceDeleter.Shutdown`'s
  existing real implementation style):
  - `func warmTemplateName(model, runtimeVersion string) string` →
    `simurgh-warm[<model>:<runtime>]`, exactly mirroring
    `cloneDeviceName`/`baseDeviceName`'s existing format functions.
  - `func (p *Provisioner) CreateWarmTemplate(ctx context.Context, spec
    broker.DeviceSpec) (broker.Device, error)`: resolve device type +
    runtime (reuse `resolveDeviceType`/`resolveRuntime`, do not
    duplicate), create a device named via `warmTemplateName`, boot it,
    wait for `Booted` (reuse the existing boot-wait logic/timeout
    constant), then shut it down, return the resulting `Device` (with
    `Booted: false`, since a warm template is deliberately left shutdown
    per the architecture — "primed, shut-down device"). Idempotent: if a
    warm template for this exact (model, runtime) already exists, return
    it as-is rather than creating a duplicate (list-check first, same
    pattern as `ensureBaseDevice`, protected by the same
    per-`(model,runtime)` lock so this doesn't race against a concurrent
    `Provision` call that's also checking for/creating a warm template
    for the same key).
  - `func (p *Provisioner) ListWarmTemplates(ctx context.Context) ([]broker.
    Device, error)`: lists live devices, filters to
    `safety.IsWarmTemplateName` (import `internal/safety` here — this is
    a new, deliberate one-directional dependency, `provisioner` → `safety`,
    consistent with `provisioner` already depending on `broker`; `safety`
    must never depend back on `provisioner`, confirm no cycle).
  - Removal does NOT belong in this file/package — `warm remove` calls
    `internal/safety.DeleteSimulatorClone` directly from the CLI/daemon
    layer (see below), reusing the exact same reviewed deletion path
    `internal/reaper.Reclaim` already uses for lease clones. Do not add a
    delete method to `internal/provisioner`.
- `internal/provisioner/provisioner.go`, `internal/provisioner/
  provisioner_test.go` — extend `Provision`'s clone-source selection: after
  resolving device type + runtime, check for an existing warm template
  (same `(model, runtime)` key, same lock scope as `ensureBaseDevice`) —
  if present, clone from ITS UDID; otherwise clone from the base device
  exactly as today. New tests: warm template present → `Clone` called
  against the warm UDID, not the base UDID (fake `SimctlClient` asserts
  which UDID `Clone` was invoked with); no warm template → existing
  base-device behavior, unchanged, existing tests still pass verbatim.
- `internal/daemon/daemon.go`, `internal/daemon/daemon_test.go` — additive
  IPC methods `warm.create`, `warm.list`, `warm.remove` (mirroring the
  existing `lease.*`/`pool.status` handler pattern exactly: wire DTOs,
  `brokerErrorToIPC`-style triple mapping — note `warm.*` errors originate
  from `internal/provisioner`/`internal/safety`, not `internal/broker`, so
  you'll need a small `provisionerErrorToIPC`/`safetyErrorToIPC` mapping
  analogous to the existing `brokerErrorToIPC`, covering
  `provisioner`'s typed errors — `DeviceTypeNotFoundError`,
  `RuntimeNotFoundError`, `CloneFailedError`, `BootTimeoutError` — and
  `safety`'s `DeviceNotManagedError`/`DeviceNotFoundError`). `warm.remove`
  calls `safety.DeleteSimulatorClone` with the target UDID (resolved by
  looking up the named warm template via `ListWarmTemplates` first — the
  CLI/wire surface takes `--model`/`--runtime`, not a raw UDID, per the
  documented CLI surface `simurgh warm create|list|remove --model ...
  --runtime ...`). `Deps` needs access to a `Provisioner` — it currently
  only holds `Broker`/`Reaper`/`LeasesRoot`; add `Provisioner *provisioner.
  Provisioner` to `Deps` (additive struct field, existing callers/tests
  that don't set it must keep working — nil-check before use, matching the
  existing `h.deps.LeasesRoot != ""` nil-guard style already in this file).
- `cmd/simurgh/warm.go` (new) — `simurgh warm create --model ... [--runtime
  ...] [--json]`, `simurgh warm list [--json]`, `simurgh warm remove
  --model ... [--runtime ...] [--json]`, matching the existing hand-rolled
  flag style and `exitCodeForIPCError`-equivalent exit mapping (extend that
  function's switch to cover the new provisioner/safety error codes rather
  than defaulting them all to 5).
- `cmd/simurgh/main.go` — wire the `warm` subcommand (with its
  `create|list|remove` sub-subcommands).
- `internal/provisioner/doc.go`, `internal/reaper/reaper.go` (the one-line
  `IsWarmTemplateName` skip in `ScanOrphans`), `internal/reaper/
  reaper_test.go` (a test proving a `simurgh-warm[...]` device is never
  returned by `ScanOrphans`/`Reconcile` even when absent from
  `knownLeaseUDIDs`).

Do not edit `internal/store`, `internal/ipc`, `internal/broker`,
`internal/watcher`, `internal/isolator`, `internal/cli`, CI config, or any

## Explicitly out of scope

- Warm **pools** (multiple pre-booted spare clones ready to hand out
  instantly) — explicitly v1 per the architecture doc.
- Any change to `internal/safety`'s deletion validation logic itself —
  `warm remove` must go through the existing, already-reviewed
  `DeleteSimulatorClone` unchanged.
- Automatic warm-template creation (e.g. "auto-warm the most popular
  spec") — v0 is manual `simurgh warm create` only.
- Config file reading, `simurgh init`, MCP.

8. **Live `[mac]` check — record real timings, this is the actual GATE
   metric** (paste verbatim; single shell, `$SIMURGH_HOME` exported once):
   (a) time a COLD acquire (`time simurgh acquire --model "iPhone 17 Pro"
   --wait --json`) with no warm template present — record the wall-clock
   acquire→ACTIVE latency; release + delete that clone; (b) `simurgh warm
   create --model "iPhone 17 Pro" --json`, confirm via `xcrun simctl list
   devices` a real `simurgh-warm[iPhone 17 Pro:27.0]` device exists and is
   `Shutdown`; (c) time a WARM acquire (same command) and confirm via a log
   line or the clone's `CloneOf` field that it cloned from the warm
   template's UDID, not the base's; record the latency; (d) compute and
   report the percentage improvement — the GATE wants ≥50%, report the
   actual number honestly whether or not it clears that bar; (e) confirm
   `xcrun simctl list devices` shows exactly base + warm-template + the one
   lease clone at each point, nothing extra; (f) `simurgh warm remove
   --model "iPhone 17 Pro"`, confirm the warm template is actually deleted,
   confirm the base is untouched; release the remaining lease + delete its
   clone; final state shows only `simurgh-base[...]`.

Return verbatim output, changed files, diff stat, and the recorded
cold-vs-warm latency numbers + percentage in your final report — do not
round up or omit an unfavorable result.

## Risk class

`low` overall — `warm remove`'s deletion reuses the existing, already-
reviewed `safety.DeleteSimulatorClone` with no new destructive primitive;
`warm create` only creates+boots+shuts-down a device (no deletion). The
`internal/provisioner.Provision` change touches the core, already-proven
clone-source-selection path (previously reviewed for a real concurrency
race in M1.2) — the reviewer should specifically re-check that adding the
warm-template lookup doesn't reopen that race (it must stay inside the
same per-`(model,runtime)` lock scope) and that the existing no-warm-
template test suite still passes byte-for-byte unmodified.
