# M2.3 work package — prune + doctor extensions

## Goal

Implement `simurgh prune [--apply]` (orphan/held/active buckets), extend
`doctor` with stale-lease and disk-usage checks, and close a real gap this
package's own design surfaced: **`Release` currently never cleans up its
device** (confirmed live in M1.5a/M1.5b/M2.2 testing — "release ≠ delete,
expected" — a clone lingers forever after a plain `release` until the
watcher's TTL/PID-death path happens to reclaim it separately, which it
often won't for a cleanly-released lease). The roadmap's own GATE example
(`simurgh release $L && simurgh prune   # plan empty`) only makes sense if
`release` triggers immediate cleanup — so wiring that is this package's
first, foundational piece; `prune`'s "held" bucket becomes a safety net for
when that immediate cleanup fails, not the primary cleanup path.

This is also where the orphan-auto-reclaim policy question — deliberately
left log-only since M1.5a, revisited and left log-only again in M1.6 —
finally gets a real, explicit, owner-visible answer: `prune --apply`
deletes discovered orphans. Automatic background deletion is still never
built; the human runs `prune --apply` on purpose.

## Source requirements

- `docs/ROADMAP.md`'s M2.3 line: "prune plan/apply with buckets
  (orphan/held/active), doctor checks for stale leases + disk usage." M2
  GATE `[mac]`: `simurgh release $L && simurgh prune   # plan empty`.
- `docs/ARCHITECTURE.md:107-133` (§4) state diagram — `RELEASED` and
  `RECLAIMED` are distinct terminal states; only `RECLAIMED` was
  documented as triggering "reaper: shutdown+delete clone." This package
  doesn't change that state-machine semantic — it wires the DAEMON's
  `release` RPC handler to ALSO invoke the reaper's teardown as an
  operational step after a successful `broker.Release`, without changing
  what state the lease ends up in (still `RELEASED`, not `RECLAIMED` —
  the bucket definitions below key off `RELEASED`/`CANCELLED`/`FAILED`
  states with a lingering `Device`, not off `RECLAIMED`).
- `internal/reaper/reaper.go` (existing) — `Reclaim(ctx, lease broker.
  Lease) error` is already state-agnostic: it deletes `lease.Device.UDID`
  (if non-nil) and `lease.ID`'s dir, with no check on `lease.State`
  inside the function itself. This means it's directly reusable for ANY
  terminal lease with a lingering device, not just ones the broker
  formally moved to `RECLAIMED` — confirm this by reading the function
  again before using it this way.
- `internal/safety` (existing, read-only) — `DeleteSimulatorClone`,
  `DeleteLeaseDir`, `IsSimurghManagedName`, `IsWarmTemplateName`. **No new
  deletion primitive in this package** — `prune --apply`'s orphan-device
  deletion calls `safety.DeleteSimulatorClone` directly (same as
  `reaper.Reclaim` already does internally); held-lease cleanup calls
  `reaper.Reclaim` (which itself only calls the same safety functions).
- `internal/reaper.ScanOrphans`/`Reconcile` (existing) — already correctly
  excludes warm templates (M2.2) and respects the 10s post-start
  reconciliation window. Reuse for the "orphan" bucket; do not re-derive
  orphan detection.

## Bucket definitions (be exact — this is the core design decision)

- **orphan**: live `simurgh-clone[...]`-named devices (never `warm[...]`,
  already excluded by `ScanOrphans`) with NO corresponding lease record at
  all in the broker (`ScanOrphans`'s existing output, fed by
  `Broker.KnownDeviceUDIDs()`). `prune --apply` deletes these via
  `safety.DeleteSimulatorClone` directly — there is no lease ID to look up
  a lease-dir for, so only the device is deleted for this bucket, never a
  lease directory.
- **held**: leases in `RELEASED`, `CANCELLED`, or `FAILED` state (terminal,
  but NOT already `RECLAIMED`) that still have a non-nil `Device` OR whose
  lease directory still exists on disk — i.e. a known lease whose
  teardown didn't (yet) happen. After this package wires immediate
  cleanup into `release` (see below), this bucket should almost always be
  empty in normal operation; it exists as the safety net for teardown
  failures (a transient `simctl` error, a daemon restart between release
  and cleanup, etc.). `prune --apply` calls `reaper.Reclaim(ctx, lease)`
  for each.
- **active**: `QUEUED`/`PROVISIONING`/`ACTIVE` leases. Informational only
  — listed in the plan for visibility, `--apply` NEVER touches this
  bucket under any circumstance.

## Exact write-set

- `internal/daemon/daemon.go`, `internal/daemon/daemon_test.go` — in the
  existing `release` handler, after `Broker.Release` succeeds, best-effort
  call `Reaper.Reclaim(ctx, lease)` if `lease.Device != nil` (mirror
  `ReclaimLoop.applyDecisions`'s existing pattern exactly: log failure via
  the same `Logger` seam already on `Deps`/`ReclaimLoop`, never fail or
  change the exit code of the `release` RPC itself just because teardown
  had a hiccup — the lease state transition is the primary contract).
  Add a test proving: release on an ACTIVE lease with a device → the fake
  `Deleter`/`Lister` sees a delete call for that UDID; release on a
  QUEUED lease (→ CANCELLED, no device) → no delete call attempted (nil
  Device is a no-op, matching `reaper.Reclaim`'s existing contract).
- `internal/reaper/prune.go` (new) — plan-building only, no side effects
  beyond the read-only calls it already makes:
  - `type PruneBucket struct { Held []broker.Lease; Orphans []string;
    Active []broker.Lease }` (`Orphans` is UDIDs, matching `ScanOrphans`'s
    existing return shape; `Held`/`Active` are full `Lease` records for
    display).
  - `func (r *Reaper) PlanPrune(ctx context.Context, allLeases []broker.
    Lease, knownDeviceUDIDs map[string]bool) (PruneBucket, error)`: takes
    the broker's full lease list (caller-supplied — this package does not
    itself hold a `*broker.Broker` reference, matching the existing
    validate/act separation and keeping `internal/reaper` from gaining a
    new broker dependency beyond the `Lease` type it already imports)
    plus the known-UDID set, buckets leases into held/active per the
    definitions above, and calls `r.Reconcile(ctx, knownDeviceUDIDs)` for
    the orphan bucket (respects the reconciliation window — an empty
    orphan bucket during that window is correct, not a bug; note this in
    the plan output if you add any status metadata, don't silently look
    identical to "genuinely zero orphans found after a real scan").
  - `internal/reaper/prune_test.go`: leases in each state land in the
    right bucket; a `RECLAIMED` lease lands in neither held nor active
    (it's already torn down, nothing to plan for it); orphan bucket
    reflects a fake lister's output correctly.
- `internal/daemon/daemon.go` (continued) — additive `prune.plan` and
  `prune.apply` IPC methods:
  - `prune.plan`: calls `Broker.List(ListFilter{})` +
    `Broker.KnownDeviceUDIDs()` + `Reaper.PlanPrune`, returns the bucket
    contents as JSON (lease summaries + orphan UDIDs). Read-only, no
    side effects.
  - `prune.apply`: **re-derives the plan fresh** (does not trust a
    client-supplied plan from an earlier `prune.plan` call — avoids
    acting on stale data), then for each `Held` lease calls
    `Reaper.Reclaim`, for each `Orphans` UDID calls
    `safety.DeleteSimulatorClone` directly (same `DeviceLister`/
    `DeviceDeleter` from `Deps` that `warm.remove`/`ReclaimLoop` already
    use), collects per-item success/failure, returns a summary (counts +
    any errors, best-effort — one failed item doesn't abort the rest,
    matching every other batch-teardown path in this codebase). Never
    touches the `Active` bucket.
- `cmd/simurgh/prune.go` (new) — `simurgh prune [--apply] [--json]`:
  no-flag → calls `prune.plan`, prints the three buckets (counts +
  brief per-item summary); `--apply` → calls `prune.apply`, prints the
  outcome summary. Exit 0 if the plan/apply call itself succeeded
  (regardless of whether the buckets were empty or non-empty — an empty
  plan and a non-empty plan are both a *successful* prune plan query, not
  an error condition); exit via the existing `exitCodeForIPCError` only on
  an actual RPC failure.
- `cmd/simurgh/main.go` — wire `prune`.
- `cmd/simurgh/doctor.go`, `internal/cli/doctor.go` (extend, following the
  exact `Check`/`RunChecks`/collect-all pattern M0.4 established — read
  it again before adding to it):
  - **Stale-lease check**: if the daemon is reachable (reuse the existing
    non-auto-starting `dialPing`-style probe this file already has — do
    not add a second daemon-liveness mechanism), call `lease.list`,
    count leases whose `state` is `active` but `expiresAt` is more than
    (say) 5 minutes in the past (should have been reclaimed by the
    watcher's 5s tick and wasn't — a real health signal, not a normal
    condition) — `ok` with 0 stale, `fail` with the count and
    `fix: "simurgh prune"` guiding toward this package's own new command
    if any are found (note: a genuinely stale ACTIVE lease isn't actually
    fixed by `prune` today since `prune` only targets terminal leases and
    orphans, not stuck-ACTIVE ones — if you find this exact gap while
    implementing, note it plainly in your report rather than writing a
    `fix` string that doesn't actually work; pick whatever `fix` text is
    honest given what `prune`/`release` can actually do about a stuck
    ACTIVE lease). If the daemon isn't reachable, this check should
    report the same "daemon not running" signal as the existing daemon
    check, not a separate confusing message — reuse, don't duplicate.
  - **Disk usage check**: compute total size under `~/.simurgh/leases/`
    (the injected leases root, matching every other package's convention)
    — `ok` always, reporting the size in the message (e.g. "leases/:
    142MB"); this is informational, not a pass/fail gate, unless you can
    justify a concrete threshold from the docs (none is specified — keep
    it informational-only, `OK: true` always, per this decision, rather
    than inventing an arbitrary threshold the spec doesn't ask for).
  - Add both to `RunChecks`'s existing collect-all list; extend the
    existing doctor tests for the two new checks (fakes for both,
    following the file's established seam-injection pattern).

Do not edit `internal/store`, `internal/ipc`, `internal/broker` (beyond
nothing — no changes to broker in this package), `internal/provisioner`,
`internal/watcher`, `internal/isolator`, `internal/safety`, CI config, or
any doc other than `docs/plans/orchestrator-state.md`.

## Explicitly out of scope

- Any new deletion primitive — every delete in this package routes through
  `reaper.Reclaim` or `safety.DeleteSimulatorClone` directly, matching
  every prior deletion-capable package.
- Automatic/scheduled prune (a cron-like "run prune every N minutes") —
  v0 is manual `simurgh prune --apply` only, run by a human on purpose.
- Fixing a stuck-ACTIVE lease (the watcher should already prevent this;
  if you find it can happen, log it as a finding, don't build a new
  recovery mechanism for it in this package).

## Risk class

`sensitive`-adjacent — `prune --apply` is a real, human-invoked deletion
surface, even though it introduces no new deletion primitive. Treat the
daemon's `prune.apply` handler and the new `release`→`reaper.Reclaim`
wiring with the same scrutiny as a sensitive package: the orchestrator
should personally confirm (not just trust a green test suite) that
`prune.apply`'s orphan-deletion path calls `safety.DeleteSimulatorClone`
(never a raw `simctl delete`), that the `active` bucket is provably never
in any code path that leads to a delete call, and that `prune.apply`
re-derives its plan fresh rather than trusting a stale client-supplied
one.
