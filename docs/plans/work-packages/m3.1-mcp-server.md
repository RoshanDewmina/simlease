# M3.1 work package — MCP server (`simurgh mcp`)

## Goal

Implement `simurgh mcp`: a stdio MCP server exposing the five tools from
`docs/ARCHITECTURE.md` §8, using the official
`github.com/modelcontextprotocol/go-sdk` (confirmed resolvable via `go list
-m -versions github.com/modelcontextprotocol/go-sdk`; pin to the latest
stable non-prerelease tag, `v1.6.1`, in `go.mod`). This is a thin
translation layer over the already-existing, already-tested
`internal/daemon` RPCs — structurally the same shape as `cmd/simurgh`'s CLI
commands (dial via `ipc.Dial`, encode/decode via `internal/ipc`), just with
an MCP tool-call interface instead of `os.Args` flags.

## Source requirements

- `docs/ARCHITECTURE.md:205-222` (§8), quoted exactly:
  ```
  | Tool | Params | Returns |
  |---|---|---|
  | lease_acquire | model, runtime?, labels?, ttl?, reuse_if_exists?, wait? | full lease grant (UDID, env, flags, expiry) |
  | lease_renew | lease_id, ttl? | new expiry |
  | lease_release | lease_id | confirmation + cleanup summary |
  | lease_status | lease_id? (default: caller's newest) | lease detail |
  | pool_status | — | capacity, active/queued leases, sims, pressure |
  ```
  "Tool descriptions are written for agent consumption: they state *when*
  to call (`"Call lease_acquire before any simulator interaction. Never
  pick a UDID from simctl yourself."`). Descriptions are part of the spec
  and reviewed like API surface." — write real, careful descriptions for
  all five tools, not placeholder text; this is explicitly called out as
  something to get right, not an afterthought.
- `internal/daemon` (existing) — the RPCs these tools wrap:
  `lease.acquire`, `lease.renew`, `lease.release`, `lease.get` (for
  `lease_status` — "default: caller's newest" means no-`lease_id` should
  fall back the same way the CLI's `release`/`env` commands already do,
  via the `~/.simurgh/last-lease` pointer — reuse
  `DefaultLastLeasePath()`, don't reinvent), `pool.status`.
- `internal/ipc.Dial` (existing) — every tool call dials through this
  (auto-starts the daemon on first use, same as every CLI command) —
  do not reimplement daemon-connection logic.
- The MCP tool `Returns` column says "full lease grant (UDID, env, flags,
  expiry)" for `lease_acquire` — this must include the `env`/
  `xcodebuildFlags` fields the daemon's wire response already populates
  (M2.1) so an agent calling this tool gets everything it needs to build
  without a follow-up `simurgh env` call.

## Exact write-set

- `go.mod`, `go.sum` — add `github.com/modelcontextprotocol/go-sdk` pinned
  to `v1.6.1` (or the latest non-prerelease tag if a newer stable one has
  shipped since this spec was written — check, don't blindly hardcode a
  stale version; do not use a `-pre` prerelease tag).
- `internal/mcp/server.go` (new) — the existing `internal/mcp` package is
  currently just a `doc.go` stub from M0.1. Implement:
  - A small internal client helper mirroring `cmd/simurgh`'s
    `dialAndCall`-equivalent (dial via `ipc.Dial` with the resolved
    socket/log paths — these path-resolution helpers currently live in
    `cmd/simurgh` as unexported functions; either export the minimal ones
    this package needs from `cmd/simurgh` — awkward, `cmd/simurgh` is
    `package main` — or duplicate the small `DefaultSocketPath`/
    `DefaultLogPath`/`DefaultLastLeasePath` logic here, consistent with
    this codebase's established "duplicate a small helper rather than
    force an awkward cross-package dependency" pattern already used
    multiple times (`internal/broker/errors.go`,
    `internal/provisioner/errors.go`, `internal/safety/errors.go` all
    duplicate rather than import). Pick the duplication approach.
  - `func NewServer() *mcp.Server` (or whatever the SDK's actual
    constructor/registration shape is — check the SDK's godoc/README via
    `go doc github.com/modelcontextprotocol/go-sdk/mcp` after `go get`,
    do not guess API shapes that don't compile) registering all five
    tools with Go structs for typed params/results (JSON-schema-derived
    from struct tags, matching whatever pattern the SDK actually expects
    — TDD this: write a test that constructs the server and asserts the
    five tool names are registered, let that drive the real
    implementation against the real SDK types).
  - Each tool handler: decode typed params → build the corresponding
    `internal/ipc` wire request → dial+call → decode the daemon's
    response → map to the tool's typed result. Errors from the daemon
    (typed `*ipc.Error`) should surface as MCP tool errors with the
    triple's `message`+`fix` folded into the error text so an agent
    calling the tool gets an actionable message, not just a bare code.
  - `lease_status` with no `lease_id`: read `~/.simurgh/last-lease`
    (same file/convention `cmd/simurgh`'s CLI already reads) and use that
    ID; if the file doesn't exist, return a clear tool error ("no lease
    acquired yet — call lease_acquire first"), not a raw file-not-found.
  - **Tool descriptions** (write these carefully, they're reviewed API
    surface per the architecture doc): each tool's description states
    when an agent should call it and what NOT to do. At minimum for
    `lease_acquire`: something like "Acquire an isolated iOS Simulator
    lease before any simulator interaction. Never pick a UDID from
    `simctl` yourself — always go through this tool. Returns the device
    UDID plus the exact env vars and xcodebuild flags to use for
    isolated builds (see the `env` and `xcodebuildFlags` fields) — pass
    these to `xcodebuild`/`simurgh exec` rather than using default
    paths." Write comparably careful descriptions for the other four —
    this is real spec work, not boilerplate.
- `internal/mcp/server_test.go` — unit tests against the daemon-facing
  seam (fake `dialAndCall`-equivalent, do not require a real running
  daemon for unit tests): each tool decodes params correctly, maps a
  successful daemon response to the right typed result shape, maps a
  daemon error to a tool error with the message/fix folded in;
  `lease_status` with no ID reads the last-lease file (use a fake/
  injected path, never the real `~/.simurgh`).
- `internal/mcp/doc.go` — update the package comment (currently a stub).
- `cmd/simurgh/mcp.go` (new) — `simurgh mcp` subcommand: constructs the
  server via `internal/mcp.NewServer()`, runs it over stdio (whatever the
  SDK's actual "run over stdio" entrypoint is called — check the SDK,
  don't guess), blocking until stdin closes or the process is signaled.
- `cmd/simurgh/main.go` — wire the `mcp` subcommand.

Do not edit `internal/store`, `internal/broker`, `internal/provisioner`,
`internal/watcher`, `internal/reaper`, `internal/safety`, `internal/
isolator`, `internal/cli`, `internal/daemon` (this package only calls its
existing RPCs over the wire, like the CLI does — it does not need daemon
changes), CI config, or any doc other than `docs/plans/orchestrator-state.md`.

## Explicitly out of scope

- `warm_*`/`prune_*` MCP tools — the architecture's documented five-tool
  surface for v0 is exactly `lease_acquire|renew|release|status` +
  `pool_status`. "Five MCP tools, not eighty" is an explicit
  non-negotiable in this project's brief — do not add more.
- `simurgh init` (M3.2, separate package) and the dogfood run (M3.3).
- Any change to the underlying `internal/daemon` RPCs — this package only
  consumes them.
