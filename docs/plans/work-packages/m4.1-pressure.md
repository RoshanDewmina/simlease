# M4.1 work package — real pressure monitoring

## Goal

Give `internal/broker`'s existing `PressureOK` seam (from M1.1, currently
always returns `true, ""`) a real implementation checking available RAM,
thermal state, and disk space before granting a lease, per
`docs/ARCHITECTURE.md` §4: "Pressure check before grant: available RAM >
4GB and thermal state nominal, else queue with reason." Also surface
pressure in `pool_status`'s response (documented in §8 as part of its
Returns: "capacity, active/queued leases, sims, pressure" — currently not
included at all).

## Design constraint — fail-open, not fail-closed

Every individual pressure signal on macOS is either shell-command-based or
uses `sysctl` names that can vary across macOS versions/hardware (confirmed
directly on this Mac: `pmset -g therm` works and prints "Note: No thermal
warning level has been recorded" when nominal; no `machdep.xcpm.cpu_thermal*`
sysctl exists on this Apple Silicon Mac, so do not hardcode an Intel-era
sysctl name). **If any individual signal can't be read or parsed, treat
that signal as OK/non-blocking and log the issue** — a detection bug must
never silently block all real usage of the product. This is a stronger
requirement than "best effort": getting pressure detection WRONG in the
fail-closed direction is worse than not having it at all.

## Source requirements

- `docs/ARCHITECTURE.md:120-124` (§4): capacity formula (already
  implemented, M1.1) plus "Pressure check before grant: available RAM >
  4GB and thermal state nominal, else queue with reason."
- `docs/ROADMAP.md`'s M4 bullet: "Pressure monitoring before grant
  (RAM/thermal/disk) with queue-reason." (disk space is this roadmap
  line's addition beyond the architecture doc's RAM/thermal — include it:
  check available disk space under the leases root's filesystem, a
  reasonable threshold like 5GB free, matching the spirit of "don't grant
  a lease you can't actually support.")
- `internal/broker/broker.go` (existing, read-only except the wiring
  below) — `BrokerOptions.PressureOK func() (bool, string)` already
  exists and is already called at the right points (`Acquire`'s grant
  check, `canGrantLocked`) — **do not change `internal/broker` at all**,
  only supply a real function for this seam from `cmd/simurgh`.
- `internal/daemon/daemon.go` (existing) — `poolStatus` handler currently
  returns `{"capacity":N,"leases":{...}}` — add a `pressure` field.

## Exact write-set

- `internal/pressure/pressure.go` (new package — the existing `internal/`
  tree has no package for this; a new small package is warranted since
  this logic is genuinely standalone, matching the pattern of
  `internal/isolator`/`internal/safety` being their own single-purpose
  packages rather than crammed into `cmd/simurgh`):
  - `type Signal struct { Name string; OK bool; Detail string }` (one per
    check — RAM, thermal, disk — for observability/pool_status display).
  - `type Report struct { OK bool; Reason string; Signals []Signal }`
    (`OK` is the AND of all signals that were actually determinable;
    `Reason` is a short human string naming which signal(s) are the
    problem, empty if OK — this is what feeds the `CAPACITY_QUEUED`-style
    error's "reason" text already wired in `internal/broker`'s
    `capacityQueued` message).
  - `func CheckRAM(minFreeBytes uint64) Signal`: parses `vm_stat` output
    (free + inactive pages × page size, matching the standard macOS
    "available-ish" approximation — do not use only "free" pages, that
    chronically under-reports on macOS due to aggressive caching) via
    `exec.Command("vm_stat")`. On any parse/exec failure, return `Signal{OK:
    true, Detail: "could not determine (treated as OK): <err>"}` — fail
    open, per the design constraint above. Default `minFreeBytes` = 4GB
    per the architecture doc.
  - `func CheckThermal() Signal`: runs `pmset -g therm`, parses for the
    absence of any "warning level" line indicating a non-nominal state
    (on this Mac, "No thermal warning level has been recorded" = nominal;
    a real warning line would say something like "CPU_Speed_Limit" below
    100 or a scheduler/speed limit note — research the actual format on a
    thermally-stressed Mac if you can find real examples online or in
    Apple docs via context7/apple-docs, otherwise treat the presence of
    any numeric limit below 100 as non-nominal and the "No ... has been
    recorded" pattern as nominal). Same fail-open-on-parse-failure rule.
  - `func CheckDisk(path string, minFreeBytes uint64) Signal`: uses
    `syscall.Statfs` (Go stdlib, darwin-supported) against `path` (the
    injected leases root — same convention as every other package, never
    resolves `~/.simurgh` itself) to compute available bytes. Default
    `minFreeBytes` = 5GB. This one has a real, reliable stdlib API — no
    fail-open needed for parse failure, but still fail-open if `Statfs`
    itself errors (e.g. path doesn't exist yet on a fresh install)
    rather than blocking a fresh install.
  - `func Check(leasesRoot string) Report`: runs all three, combines.
- `internal/pressure/pressure_test.go` — unit tests: `CheckDisk` against a
  real `t.TempDir()` (this one doesn't need fake seams, `Statfs` on a real
  temp dir is fast and deterministic-enough for a pass/fail-threshold
  test — use a threshold high enough that it reliably passes, e.g. 1 byte,
  and one deliberately absurd threshold like 1 exabyte to prove the
  `false` path works too); `CheckRAM`/`CheckThermal` unit tests should
  inject a fake command runner (small seam, e.g. `type runner
  func(name string, args ...string) ([]byte, error)`, defaulting to a real
  `exec.Command(...).Output()`), covering: real-shaped output → correct
  parse; garbage/empty output → fail-open (`OK: true`); command-not-found
  error → fail-open.
- `internal/daemon/daemon.go` — `poolStatus` handler gains a `pressure`
  field in its JSON response (marshal `pressure.Report`, or a trimmed
  view of it — your call, keep the wire shape reasonable). This requires
  `Deps` to gain a way to compute pressure — simplest: `Deps.LeasesRoot`
  already exists, so `poolStatus` can call `pressure.Check(h.deps.
  LeasesRoot)` directly at request time (no need to store a `Report` on
  `Deps` — it's cheap enough to compute fresh per `pool_status` call,
  consistent with this codebase's existing "recompute pure things fresh
  rather than cache" pattern from M2.1's isolation env).
- `cmd/simurgh/daemon.go` — wire a real `PressureOK` function into
  `broker.New(broker.BrokerOptions{...})`: `func() (bool, string) { r :=
  pressure.Check(leasesRoot); return r.OK, r.Reason }`.
- `internal/mcp/server.go` — `pool_status` tool's result type should
  mirror the new `pressure` field (architecture's own tools table already
  documents `pool_status`'s Returns as including "pressure" — this closes
  that gap in the MCP surface too, matching the daemon wire response).

Do not edit `internal/store`, `internal/broker` (the seam already exists,
do not touch its logic), `internal/provisioner`, `internal/watcher`,
`internal/reaper`, `internal/safety`, `internal/isolator`, `internal/ipc`,
`internal/cli`, CI config, or any doc other than
`docs/plans/orchestrator-state.md`.

## Explicitly out of scope

- Continuous/background pressure monitoring — this is checked at grant
  time only (`Acquire`), matching the architecture's "before grant"
  wording, not a polling loop.
- Any change to the capacity FORMULA (`ComputeCapacity`) — pressure is a
  separate, additional gate on top of capacity, not a replacement for it.
- Disk-space-based pruning/cleanup automation — that's informational only
  here (feeds `pool_status` and the grant gate), not a trigger for
  `prune`.
