# M4.3 work package — error-message audit

## Goal

A mechanical, repo-wide check proving every error-triple (code + message +
fix) constructed anywhere in this codebase is genuinely non-empty at every
call site — not just that the runtime validators would catch an empty
value if one slipped through (they already do, in every package). This is
primarily a verification task over already-correct code, per
`docs/REVIEW_STANDARDS.md`'s existing rule ("Every user-facing error must
include a stable code, a human message, and an exact fix command"), not new
functionality.

## Source requirements

- `docs/ROADMAP.md`'s M4 bullet: "Error-message audit: every error path
  has code+message+fix (grep-able test)."
- Confirmed error-triple constructors in this codebase (survey already
  run): `internal/broker/errors.go`, `internal/provisioner/errors.go`,
  `internal/safety/errors.go`, `internal/ipc/protocol.go` — each already
  has its own local `NewError(code, message, fix string) (*Error, error)`
  (or equivalent) that returns an error if any of the three is empty
  (confirmed present in every one already, from prior packages this
  session). This package's job is NOT to add that validation — it already
  exists everywhere — but to prove no call site actually passes an empty
  literal, which the runtime validator alone can't catch until that code
  path actually executes (which most don't, in normal test runs).

## Design — AST-based static check, not fragile regex

Use `go/parser` + `go/ast` (Go stdlib, no new dependency) to walk every
`.go` source file in this module (excluding `_test.go` files and the
`test/fixtures/SampleApp` fixture, which is a separate Xcode project, not
Go source) and find every call expression whose function name is
`NewError` (regardless of package — there are 4 independent local
definitions, by design, per this codebase's established "duplicate small
helpers rather than force a shared package" convention). For each call,
inspect its first three arguments: if any is a `*ast.BasicLit` string
literal with value `""` (empty), flag it as a failing case (file:line +
the exact call). Calls that pass a variable/expression (not a literal) are
NOT flagged by the static check — those are covered by each package's
existing runtime validation instead; note this scope boundary explicitly
in the tool/test's own doc comment, don't overclaim static coverage it
doesn't have.

## Exact write-set

- `internal/errortriple/audit.go` (new small package) — exports `func
  Audit(rootDir string) ([]Finding, error)` where `Finding{File string;
  Line int; Snippet string}` — the reusable AST-walk logic described
  above. `rootDir` injected (test uses this repo's own root, or a
  constructed fixture dir for the "detects a real violation" test case —
  see below).
- `internal/errortriple/audit_test.go`:
  - A test that runs `Audit` against a small SYNTHETIC fixture directory
    (`t.TempDir()` with a couple of hand-written `.go` files containing
    both a valid `NewError("CODE", "message", "fix")` call and a
    deliberately broken `NewError("", "message", "fix")` call) — confirms
    the audit correctly flags exactly the broken one and not the valid
    one. This proves the audit tool itself actually works, not just that
    it runs without crashing.
  - **The real audit**, run against this actual repo:
    `TestNoEmptyErrorTripleLiteralsInRepo(t *testing.T)` calls `Audit`
    against the module root (resolve it via `go list -m -f
    '{{.Dir}}'`-equivalent, or simplest: walk up from the test file's own
    directory to find `go.mod` — do not hardcode an absolute path) and
    fails the test with every finding printed (file:line + snippet) if
    the result is non-empty. This is the actual "grep-able test" the
    roadmap asks for, running as part of the normal `go test ./...` suite
    from now on — any future PR that accidentally introduces an empty
    error-triple literal fails CI/local tests automatically.
- `internal/errortriple/doc.go` — package comment explaining the scope
  boundary (literal-only static check; runtime validation is each
  constructor's own existing job).

Do not edit `internal/broker`, `internal/provisioner`, `internal/safety`,
`internal/ipc`, or any other existing package — if the audit finds a real
violation in existing code (it shouldn't, given every prior package's own
review already checked this), report it and let the orchestrator decide
the fix rather than silently patching a different package as a side
effect of this one.

## Explicitly out of scope

- Runtime/dynamic verification of every error path (e.g. actually
  triggering every one of the ~20+ distinct error conditions across the
  codebase end-to-end) — that's what each package's own existing test
  suite already does at the unit level; this package adds the static
  literal-safety net on top, not a replacement.
- Any change to how errors are constructed or validated in any existing
  package.

## Acceptance commands

1. `gofmt -w internal/errortriple`
2. `go test -race ./internal/errortriple/... -v` (paste full output,
   including the real-repo audit test's pass/fail and finding count)
3. `go build ./...`
4. `go vet ./...`
5. `go test -race ./...`
6. `$(go env GOPATH)/bin/staticcheck ./...`
7. `git diff --check`

No live `[mac]` check needed for this package — it's a pure static-analysis
tool over source code, nothing simctl/daemon-related.

Return verbatim output, changed files, diff stat, and the exact count of
`NewError` call sites the audit examined across the repo (a sanity number
proving it actually walked the whole tree, not just one package) plus
confirmation the real-repo audit test passes with zero findings (or, if it
finds something real, report that honestly instead of suppressing it).

## Risk class

`low` — pure static analysis, no runtime behavior change anywhere.
Standard review pipeline (or the orchestrator's own direct read, given how
small and mechanical this is).
